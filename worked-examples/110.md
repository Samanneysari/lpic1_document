## 110.1 Security administration

### What this objective teaches

Audit identities, special permissions, open ports, resource limits, login history, and sudo policy.

### Worked example 1: Find SUID files

```bash
find /usr/bin /usr/sbin -xdev -type f -perm -4000 2>/dev/null
```

**Line-by-line explanation:**

1. `find` stays on each starting filesystem, selects regular files with every SUID bit in `4000`, and hides permission errors.

**What to verify:** Every result deserves an owner, package, and business-purpose check.

### Worked example 2: Read current limits

```bash
ulimit -a
```

**Line-by-line explanation:**

1. The shell builtin `ulimit -a` prints all resource limits applied to the current shell and its future children.

**What to verify:** Soft limits can be lower than hard limits and may use different units.

### Worked example 3: Review recent logins

```bash
last -n 10
```

**Line-by-line explanation:**

1. `last` reads the login history database and `-n 10` limits output to ten records.

**What to verify:** Unexpected accounts, times, or source addresses require investigation.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 110.2 Host security

### What this objective teaches

Reduce attack surface, protect password data, disable unused services, and recognize legacy access controls.

### Worked example 1: List enabled services

```bash
systemctl list-unit-files --type=service --state=enabled
```

**Line-by-line explanation:**

1. `list-unit-files` reads installation state; the filters keep service units enabled for activation.

**What to verify:** Enabled does not prove running now; confirm with `is-active`.

### Worked example 2: List listening endpoints

```bash
sudo ss -lntup
```

**Line-by-line explanation:**

1. `ss` lists listening TCP and UDP sockets numerically; `sudo` improves access to owning-process information.

**What to verify:** Compare each listener with the services the host actually needs.

### Worked example 3: Check shadow permissions

```bash
stat -c '%A %U %G %n' /etc/shadow
```

**Line-by-line explanation:**

1. `stat -c` prints symbolic permissions, owner, group, and path for the shadow password file.

**What to verify:** The file must not be readable by ordinary users.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 110.3 Encryption and secure communications

### What this objective teaches

Use SSH host verification, keys and tunnels, plus GnuPG encryption, signing, and revocation planning.

### Worked example 1: Inspect an SSH public key

```bash
ssh-keygen -lf "$HOME/.ssh/id_ed25519.pub"
```

**Line-by-line explanation:**

1. `ssh-keygen -l` prints a fingerprint and `-f` selects the public-key file; it does not reveal the private key.

**What to verify:** If the file does not exist, create a key pair deliberately before retrying.

### Worked example 2: List GnuPG keys

```bash
gpg --list-keys --keyid-format long
```

**Line-by-line explanation:**

1. `gpg --list-keys` reads public keys and `--keyid-format long` avoids short ambiguous IDs.

**What to verify:** Public keys, user IDs, and capabilities appear; private material is not printed.

### Worked example 3: Check an SSH server key

```bash
ssh-keyscan -t ed25519 localhost 2>/dev/null | ssh-keygen -lf -
```

**Line-by-line explanation:**

1. `ssh-keyscan` fetches the presented public host key, the pipe passes it to `ssh-keygen`, and `-f -` reads from standard input for a fingerprint.

**What to verify:** Scanning does not establish trust; compare the fingerprint through a trusted channel.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.
