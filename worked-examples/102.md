## 102.1 Disk layout

### What this objective teaches

Separate disks, partitions, filesystems, mount points, swap, and the three LVM layers.

### Worked example 1: Map storage

```bash
lsblk -f
```

**Line-by-line explanation:**

1. `lsblk` displays block devices; `-f` adds filesystem type, label, UUID, and mount points.

**What to verify:** Indented rows show which partitions belong to each disk.

### Worked example 2: Find the root source

```bash
findmnt /
```

**Line-by-line explanation:**

1. `findmnt` searches mounted filesystems; `/` asks for the filesystem mounted as the root directory.

**What to verify:** The SOURCE field may be a partition, mapper device, or logical volume.

### Worked example 3: List active swap

```bash
swapon --show
```

**Line-by-line explanation:**

1. `swapon` manages swap; `--show` only reports the swap areas that are active.

**What to verify:** No output means no swap area is currently active.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 102.2 Boot manager

### What this objective teaches

Read GRUB sources and generated configuration without confusing configuration generation with bootloader installation.

### Worked example 1: Read common GRUB settings

```bash
grep '^GRUB_' /etc/default/grub
```

**Line-by-line explanation:**

1. `grep` selects lines beginning with `GRUB_`; `^` anchors the match at the start of each line.

**What to verify:** You may see timeout, default-entry, and kernel-command-line settings.

### Worked example 2: List generator scripts

```bash
ls -1 /etc/grub.d
```

**Line-by-line explanation:**

1. `ls -1` prints one entry per line from the directory whose scripts build the GRUB 2 menu.

**What to verify:** Numbered script names normally control their processing order.

### Worked example 3: Find installed kernels

```bash
find /boot -maxdepth 1 -type f -name 'vmlinuz*'
```

**Line-by-line explanation:**

1. `find` searches `/boot`; the options stay at one level, require files, and match names beginning with `vmlinuz`.

**What to verify:** Each result is an installed kernel image, not proof that GRUB has a working entry.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 102.3 Shared libraries

### What this objective teaches

See how dynamically linked programs find reusable library code.

### Worked example 1: Identify an executable

```bash
file /bin/ls
```

**Line-by-line explanation:**

1. `file` inspects `/bin/ls` and reports its format, architecture, and whether it is dynamically linked.

**What to verify:** Most distributions report an ELF executable.

### Worked example 2: List library dependencies

```bash
ldd /bin/ls
```

**Line-by-line explanation:**

1. `ldd` asks the trusted executable's dynamic loader to show required libraries and resolved paths.

**What to verify:** `not found` marks an unresolved dependency; do not run `ldd` on an untrusted file.

### Worked example 3: Read the loader cache

```bash
ldconfig -p
```

**Line-by-line explanation:**

1. `ldconfig -p` prints the current shared-library cache without rebuilding it.

**What to verify:** The output maps library names to paths for one or more architectures.

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 102.4 Debian package management

### What this objective teaches

Use APT for repositories and dependency solving, and dpkg for the local package database.

### Worked example 1: Inspect a package

```bash
apt show bash
```

**Line-by-line explanation:**

1. `apt show` displays repository metadata for the `bash` package without changing the system.

**What to verify:** Read the version, dependencies, description, and download size.

### Worked example 2: List installed files

```bash
dpkg -L bash
```

**Line-by-line explanation:**

1. `dpkg -L` asks the local dpkg database for paths installed by the `bash` package.

**What to verify:** The list includes binaries, documentation, and package-managed directories.

### Worked example 3: Find a file's owner

```bash
dpkg -S /bin/bash
```

**Line-by-line explanation:**

1. `dpkg -S` searches installed-package records for the exact path `/bin/bash`.

**What to verify:** The result begins with the owning package name; merged `/usr` layouts may use another stored path.

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 102.5 RPM, YUM, DNF, and Zypper

### What this objective teaches

Use repository managers for dependencies and RPM for installed-package queries.

### Worked example 1: Inspect installed Bash

```bash
rpm -qi bash
```

**Line-by-line explanation:**

1. `rpm -q` enters query mode and `-i` requests information about the installed `bash` package.

**What to verify:** This is a query; it is different from `rpm -i file.rpm`, which installs a file.

### Worked example 2: List package files

```bash
rpm -ql bash
```

**Line-by-line explanation:**

1. `-q` queries the package and `-l` lists its installed paths.

**What to verify:** The output should include the Bash executable and documentation.

### Worked example 3: Find a provider

```bash
dnf provides '*/bash'
```

**Line-by-line explanation:**

1. `dnf provides` searches enabled repositories; the quoted glob asks for packages containing a path ending in `/bash`.

**What to verify:** Repository metadata must be available; the result can include several versions.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 102.6 Linux as a virtualization guest

### What this objective teaches

Distinguish virtual machines, system containers, application containers, images, and clone identity.

### Worked example 1: Detect virtualization

```bash
systemd-detect-virt
```

**Line-by-line explanation:**

1. `systemd-detect-virt` reports a recognized VM or container technology and returns a useful exit status.

**What to verify:** A result such as `kvm`, `docker`, or `none` describes the current environment.

### Worked example 2: Read machine identity

```bash
cat /etc/machine-id
```

**Line-by-line explanation:**

1. `cat` prints the local machine ID used by system software; cloned guests should not accidentally share it.

**What to verify:** A normal installed system shows one hexadecimal identifier.

### Worked example 3: Inspect cloud-init

```bash
cloud-init status --long
```

**Line-by-line explanation:**

1. `cloud-init status` reports initialization state; `--long` includes detailed stage and error information.

**What to verify:** If cloud-init is absent, the shell reports that the command is not installed.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.
