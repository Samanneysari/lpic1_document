## 103.1 Work on the command line

### What this objective teaches

Understand command lookup, quoting, variables, history, manuals, and exit status.

### Worked example 1: Find how a command resolves

```bash
type -a printf
```

**Line-by-line explanation:**

1. `type` asks the shell how `printf` resolves; `-a` lists every matching alias, builtin, function, or executable.

**What to verify:** Bash normally reports a builtin and may also report an external executable.

### Worked example 2: Protect spaces with quotes

```bash
printf '%s\n' 'two words'
```

**Line-by-line explanation:**

1. `printf` uses `%s` for one string and `\n` for a newline; quotes keep `two words` as one argument.

**What to verify:** The output is one line containing `two words`.

### Worked example 3: Read the previous status

```bash
printf 'status=%s\n' \"$?\"
```

**Line-by-line explanation:**

1. `$?` expands to the previous command's exit status; double quotes keep the expanded value as one argument.

**What to verify:** Zero normally means success; a nonzero value describes some kind of failure.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 103.2 Process text streams

### What this objective teaches

Select, transform, sort, count, join, split, checksum, and decompress text.

### Worked example 1: Count login shells

```bash
cut -d: -f7 /etc/passwd | sort | uniq -c
```

**Line-by-line explanation:**

1. `cut` selects colon-separated field 7, the pipe passes it to `sort`, and `uniq -c` counts adjacent equal shell paths.

**What to verify:** Each output line contains a count followed by a shell path.

### Worked example 2: Number the first rows

```bash
head -n 5 /etc/passwd | nl -ba
```

**Line-by-line explanation:**

1. `head -n 5` keeps five lines; the pipe sends them to `nl`, where `-ba` numbers all lines.

**What to verify:** Five numbered account records appear.

### Worked example 3: Create a checksum

```bash
sha256sum /etc/hosts
```

**Line-by-line explanation:**

1. `sha256sum` reads `/etc/hosts` and calculates a SHA-256 digest without changing the file.

**What to verify:** The digest and filename appear; identical bytes produce the same digest.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 103.3 Basic file management

### What this objective teaches

Create, copy, move, find, archive, compress, and safely remove files.

### Worked example 1: Create a practice tree

```bash
mkdir -p /tmp/lpic-example/docs
```

**Line-by-line explanation:**

1. `mkdir` creates directories; `-p` creates missing parent directories and does not fail if they already exist.

**What to verify:** The path `/tmp/lpic-example/docs` exists afterward.

### Worked example 2: Find recent text files

```bash
find /tmp/lpic-example -type f -name '*.txt' -mtime -1
```

**Line-by-line explanation:**

1. `find` searches the practice tree for files whose names end in `.txt` and whose data changed less than one day ago.

**What to verify:** Only matching paths are printed; an empty result is valid.

### Worked example 3: Archive the tree

```bash
tar -czf /tmp/lpic-example.tgz -C /tmp lpic-example
```

**Line-by-line explanation:**

1. `tar` creates (`-c`) a gzip archive (`-z`) at the file named after `-f`; `-C /tmp` changes directory before adding the tree.

**What to verify:** The archive stores relative paths below `lpic-example`.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 103.4 Streams, pipes, and redirection

### What this objective teaches

Control standard input, standard output, standard error, pipelines, tee, and xargs.

### Worked example 1: Separate output and errors

```bash
ls /etc /missing > /tmp/ls.out 2> /tmp/ls.err
```

**Line-by-line explanation:**

1. `>` sends file descriptor 1 to `ls.out`; `2>` separately sends file descriptor 2 to `ls.err`.

**What to verify:** The valid listing and missing-path error land in different files.

### Worked example 2: See and save output

```bash
printf 'alpha\nbeta\n' | tee /tmp/names.txt
```

**Line-by-line explanation:**

1. `printf` produces two lines, the pipe feeds `tee`, and `tee` writes both to the screen and `names.txt`.

**What to verify:** The same two lines appear in both places.

### Worked example 3: Turn input into arguments safely

```bash
printf '%s\0' 'two words' | xargs -0 printf '<%s>\n'
```

**Line-by-line explanation:**

1. `printf` emits a NUL-terminated item; `xargs -0` reads that safe delimiter and calls the final `printf` with one argument.

**What to verify:** The output is `<two words>` on one line.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 103.5 Processes and jobs

### What this objective teaches

Observe processes, manage shell jobs, and send the least disruptive useful signal.

### Worked example 1: List your processes

```bash
ps -u "$USER" -o pid,ppid,stat,comm
```

**Line-by-line explanation:**

1. `ps -u` selects your account and `-o` chooses process ID, parent ID, state, and command columns.

**What to verify:** Use PID and PPID to see parent-child relationships.

### Worked example 2: Find a process

```bash
pgrep -a bash
```

**Line-by-line explanation:**

1. `pgrep` searches process names for `bash`; `-a` adds each full command line.

**What to verify:** Every matching PID appears with its command, or there is no output.

### Worked example 3: Watch load briefly

```bash
uptime
```

**Line-by-line explanation:**

1. `uptime` prints current time, running duration, logged-in user count, and 1-, 5-, and 15-minute load averages.

**What to verify:** Load is runnable or uninterruptible work, not a direct CPU percentage.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 103.6 Process priorities

### What this objective teaches

Read nice values, start work with a chosen priority, and adjust permitted running processes.

### Worked example 1: Read nice values

```bash
ps -o pid,ni,comm -p $$
```

**Line-by-line explanation:**

1. `ps -p $$` selects the current shell because `$$` expands to its PID; `-o` selects PID, nice value, and command.

**What to verify:** A normal shell often has nice value 0.

### Worked example 2: Start lower-priority work

```bash
nice -n 10 sleep 2
```

**Line-by-line explanation:**

1. `nice -n 10` starts `sleep 2` with a niceness adjustment of 10, giving it less CPU preference under contention.

**What to verify:** The command normally finishes silently after about two seconds.

### Worked example 3: Inspect priority in top

```bash
top -b -n 1 -p $$
```

**Line-by-line explanation:**

1. `top -b` uses batch output, `-n 1` takes one sample, and `-p $$` limits it to the current shell.

**What to verify:** The NI column shows niceness; PR is the scheduler priority display.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 103.7 Regular expressions

### What this objective teaches

Match text with anchors, classes, repetition, grouping, and basic or extended syntax.

### Worked example 1: Match an exact prefix

```bash
grep '^root:' /etc/passwd
```

**Line-by-line explanation:**

1. `grep` uses a basic regular expression; `^` means start of line and `root:` is literal text.

**What to verify:** The local root account record is normally printed.

### Worked example 2: Use extended alternation

```bash
printf '%s\n' cat dog fox | grep -E '^(cat|dog)$'
```

**Line-by-line explanation:**

1. `printf` emits three lines; `grep -E` enables extended regex, where the group chooses `cat` or `dog` and both anchors require a whole-line match.

**What to verify:** Only `cat` and `dog` remain.

### Worked example 3: Replace repeated space

```bash
printf 'a   b\n' | sed -E 's/ +/ /g'
```

**Line-by-line explanation:**

1. `sed -E` uses extended regex; `s/ +/ /g` replaces every run of one or more spaces with one space.

**What to verify:** The result is `a b`.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 103.8 Basic file editing

### What this objective teaches

Use vi modes, movement, editing, search, save, quit, and the default-editor variable.

### Worked example 1: Open a safe practice file

```bash
vi /tmp/vi-practice.txt
```

**Line-by-line explanation:**

1. `vi` opens the named file; it creates the file only when you save it.

**What to verify:** You begin in Normal mode; press `i` to insert text and `Esc` to return.

### Worked example 2: Choose a default editor

```bash
EDITOR=vi sh -c 'printf "%s\n" "$EDITOR"'
```

**Line-by-line explanation:**

1. `EDITOR=vi` sets a variable only for `sh`; `sh -c` runs the quoted command, which prints the inherited value.

**What to verify:** The output is `vi`, while the parent shell remains unchanged.

### Worked example 3: Read vi help

```bash
man vi
```

**Line-by-line explanation:**

1. `man` opens the installed manual page for `vi`; use `/pattern` to search and `q` to leave the manual viewer.

**What to verify:** The exact manual can describe vi, Vim in compatible mode, or another implementation.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.
