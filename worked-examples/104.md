## 104.1 Partitions and filesystems

### What this objective teaches

Recognize partition tables and filesystem-creation tools without risking a real disk.

### Worked example 1: Inspect partition tables

```bash
sudo fdisk -l
```

**Line-by-line explanation:**

1. `fdisk -l` lists known disks and partition tables; `sudo` may be required to read every device.

**What to verify:** Treat device names as evidence to verify, never as assumptions for a write command.

### Worked example 2: Read filesystem signatures

```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,LABEL,UUID,MOUNTPOINTS
```

**Line-by-line explanation:**

1. `lsblk -o` prints only the named storage columns, including identity and current use.

**What to verify:** A blank FSTYPE can mean no recognized filesystem or an intermediate storage layer.

### Worked example 3: Inspect one filesystem tool

```bash
mkfs.ext4 -V
```

**Line-by-line explanation:**

1. `mkfs.ext4 -V` prints version information; no device argument is supplied, so no filesystem is created.

**What to verify:** Use creation commands only on a positively identified disposable device.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 104.2 Filesystem integrity

### What this objective teaches

Measure space and inodes, understand offline checks, and keep ext and XFS repair tools separate.

### Worked example 1: Check free space

```bash
df -hT
```

**Line-by-line explanation:**

1. `df` reports mounted filesystem capacity; `-h` uses readable sizes and `-T` adds filesystem type.

**What to verify:** Use the mount point to identify the filesystem that is becoming full.

### Worked example 2: Check inode use

```bash
df -i
```

**Line-by-line explanation:**

1. `df -i` reports inode counts instead of data blocks.

**What to verify:** A filesystem can reject new files when inodes are full even if bytes remain.

### Worked example 3: Measure one directory

```bash
du -sh /var/log
```

**Line-by-line explanation:**

1. `du` totals allocated space below `/var/log`; `-s` gives one summary and `-h` uses readable units.

**What to verify:** Permission errors can make an unprivileged total incomplete.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 104.3 Mounting and unmounting

### What this objective teaches

Map devices to directories, read fstab, and verify that unmounting really succeeded.

### Worked example 1: Inspect the root mount

```bash
findmnt /
```

**Line-by-line explanation:**

1. `findmnt /` reports the source, target, filesystem type, and options for the root mount.

**What to verify:** The source may be an UUID-resolved device or mapper path.

### Worked example 2: Read stable identifiers

```bash
blkid
```

**Line-by-line explanation:**

1. `blkid` reads recognized block-device signatures and identifiers; root privileges may reveal more devices.

**What to verify:** UUIDs are usually safer than changing `/dev/sdX` names in `/etc/fstab`.

### Worked example 3: Validate fstab syntax

```bash
findmnt --verify --verbose
```

**Line-by-line explanation:**

1. `findmnt --verify` checks `/etc/fstab`; `--verbose` explains warnings and errors without mounting everything.

**What to verify:** Fix reported syntax or missing-device problems before rebooting.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 104.5 Permissions and ownership

### What this objective teaches

Read and change owner, group, mode bits, special bits, and the creation mask.

### Worked example 1: Read symbolic and numeric modes

```bash
stat -c '%A %a %U %G %n' /etc/passwd
```

**Line-by-line explanation:**

1. `stat -c` uses the format to print symbolic mode, octal mode, owner, group, and filename.

**What to verify:** A common result begins with `-rw-r--r-- 644 root root`.

### Worked example 2: See the current mask

```bash
umask
```

**Line-by-line explanation:**

1. `umask` prints the shell's file-creation mask, commonly in octal.

**What to verify:** A mask of `0022` removes group and other write bits from default modes.

### Worked example 3: Practice a private mode

```bash
chmod 600 /tmp/lpic-example-file
```

**Line-by-line explanation:**

1. `chmod 600` gives the owner read and write permission and removes all group and other permissions.

**What to verify:** Create the practice file first; then verify with `stat` or `ls -l`.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 104.6 Hard and symbolic links

### What this objective teaches

Compare shared-inode hard links with path-based symbolic links.

### Worked example 1: Create a symbolic link

```bash
ln -s /etc/hosts /tmp/hosts-link
```

**Line-by-line explanation:**

1. `ln -s` creates a symbolic link whose stored target text is `/etc/hosts`.

**What to verify:** The link has its own inode and can cross filesystem boundaries.

### Worked example 2: Inspect link text

```bash
readlink /tmp/hosts-link
```

**Line-by-line explanation:**

1. `readlink` prints the target text stored in the symbolic link.

**What to verify:** The result is `/etc/hosts`; it does not copy the file.

### Worked example 3: Compare inode numbers

```bash
ls -li /etc/hosts /tmp/hosts-link
```

**Line-by-line explanation:**

1. `ls -l` shows details and `-i` adds inode numbers for the original path and the symbolic link.

**What to verify:** The inode numbers differ because a symbolic link is a separate object.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 104.7 Filesystem hierarchy and file location

### What this objective teaches

Know the purpose of key FHS directories and choose the correct search tool.

### Worked example 1: Find executable resolution

```bash
type -a sh
```

**Line-by-line explanation:**

1. The shell builtin `type` explains every way `sh` resolves, including aliases, functions, builtins, and PATH entries.

**What to verify:** This is more complete than assuming `which` reports every shell-level match.

### Worked example 2: Find manual and binary paths

```bash
whereis passwd
```

**Line-by-line explanation:**

1. `whereis` searches standard locations for the command's binary, source, and manual pages.

**What to verify:** It is a quick indexed-location query, not a full filesystem search.

### Worked example 3: Search by exact filename

```bash
find /etc -type f -name 'hosts' 2>/dev/null
```

**Line-by-line explanation:**

1. `find` walks `/etc`, keeps regular files named `hosts`, and redirects permission errors from descriptor 2.

**What to verify:** The normal result includes `/etc/hosts`.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.
