## 105.1 Shell environment

### What this objective teaches

Control local and exported variables, startup files, aliases, functions, and skeleton files.

### Worked example 1: Compare local and exported data

```bash
demo=value; export demo; printenv demo
```

**Line-by-line explanation:**

1. The first command creates a shell variable, `export` marks it for child processes, and `printenv` reads it from the environment.

**What to verify:** The output is `value`.

### Worked example 2: Inspect PATH entries

```bash
printf '%s\n' \"$PATH\" | tr ':' '\n'
```

**Line-by-line explanation:**

1. `printf` emits PATH, the pipe passes it to `tr`, and `tr` changes each colon separator into a newline.

**What to verify:** Each command-search directory appears on its own line.

### Worked example 3: Load a file in this shell

```bash
printf 'course_var=ready\n' > /tmp/lpic-env; . /tmp/lpic-env; printf '%s\n' \"$course_var\"
```

**Line-by-line explanation:**

1. The first command writes an assignment, `.` sources it in the current shell, and the last command prints the new shell variable.

**What to verify:** The output is `ready`; review a file before sourcing it.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 105.2 Simple shell scripts

### What this objective teaches

Write predictable scripts with a shebang, arguments, tests, loops, substitution, and exit status.

### Worked example 1: Test for a directory

```bash
if test -d /etc; then echo 'exists'; else echo 'missing'; fi
```

**Line-by-line explanation:**

1. `if` runs `test -d /etc`; `then` handles success, `else` handles failure, and `fi` ends the conditional.

**What to verify:** A normal Linux system prints `exists`.

### Worked example 2: Loop over arguments

```bash
for item in one two three; do printf '%s\n' \"$item\"; done
```

**Line-by-line explanation:**

1. `for` assigns each word to `item`; `do` starts the body, quoting preserves the value, and `done` ends the loop.

**What to verify:** The three words print on separate lines.

### Worked example 3: Use command substitution

```bash
kernel=$(uname -r); printf 'kernel=%s\n' \"$kernel\"
```

**Line-by-line explanation:**

1. `$(uname -r)` captures the running kernel release into `kernel`; the second command prints it safely.

**What to verify:** The result begins with `kernel=` followed by the release.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.
