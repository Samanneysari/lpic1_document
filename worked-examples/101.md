## 101.1 Hardware settings

### What this objective teaches

Learn how Linux discovers hardware, exposes devices, and loads drivers.

### Worked example 1: Inspect the CPU

```bash
lscpu
```

**Line-by-line explanation:**

1. `lscpu` reads CPU architecture and topology information collected by the kernel.

**What to verify:** Look for Architecture, CPU(s), Core(s) per socket, and Virtualization.

### Worked example 2: Inspect memory

```bash
free -h
```

**Line-by-line explanation:**

1. `free` reports RAM and swap; `-h` changes byte counts into readable units such as MiB and GiB.

**What to verify:** Use the `available` column when estimating memory that new programs can use.

### Worked example 3: Match hardware to a driver

```bash
lspci -nnk
```

**Line-by-line explanation:**

1. `lspci` lists PCI devices; `-nn` includes numeric IDs and `-k` shows the kernel driver and possible modules.

**What to verify:** For a device, `Kernel driver in use` names the active driver.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 101.2 Boot the system

### What this objective teaches

Follow the boot path from firmware through GRUB, the kernel, initramfs, and PID 1.

### Worked example 1: Read kernel arguments

```bash
cat /proc/cmdline
```

**Line-by-line explanation:**

1. `cat` prints the virtual file `/proc/cmdline`, which contains the arguments used for this boot.

**What to verify:** You may see options such as `root=`, `ro`, or `quiet`.

### Worked example 2: Identify PID 1

```bash
ps -p 1 -o pid,comm,args
```

**Line-by-line explanation:**

1. `ps` reads process data; `-p 1` selects PID 1 and `-o` chooses the three displayed columns.

**What to verify:** The command column usually shows `systemd` on a current distribution.

### Worked example 3: Read this boot's messages

```bash
journalctl -b --no-pager -n 20
```

**Line-by-line explanation:**

1. `journalctl` reads the journal; `-b` selects this boot, `--no-pager` prints directly, and `-n 20` keeps the last 20 entries.

**What to verify:** The newest 20 journal records appear; permissions may limit the result.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 101.3 Runlevels, targets, shutdown, and reboot

### What this objective teaches

Understand current systemd targets, future boot defaults, service state, and safe shutdown.

### Worked example 1: Read the future boot target

```bash
systemctl get-default
```

**Line-by-line explanation:**

1. `systemctl` talks to systemd; `get-default` prints the target selected for future normal boots.

**What to verify:** Do not treat this as a list of every target active now.

### Worked example 2: List active targets

```bash
systemctl list-units --type=target --state=active
```

**Line-by-line explanation:**

1. `list-units` lists loaded units; the two filters keep only active target units.

**What to verify:** Several targets can be active at the same time.

### Worked example 3: Check a service precisely

```bash
systemctl is-active ssh.service
```

**Line-by-line explanation:**

1. `is-active` tests whether `ssh.service` is running now; replace the name if your distribution uses `sshd.service`.

**What to verify:** The text and exit status distinguish active from inactive or unknown.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.
