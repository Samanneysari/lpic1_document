## 108.1 System time

### What this objective teaches

Separate system time, hardware clock, time zone, and network synchronization.

### Worked example 1: Print an unambiguous timestamp

```bash
date --iso-8601=seconds
```

**Line-by-line explanation:**

1. `date` reads system time; `--iso-8601=seconds` includes date, time, seconds, and numeric UTC offset.

**What to verify:** The offset makes the timestamp understandable across time zones.

### Worked example 2: Read synchronization state

```bash
timedatectl show -p NTPSynchronized -p Timezone
```

**Line-by-line explanation:**

1. `timedatectl show` exposes machine-readable properties; the two `-p` options select NTP state and zone.

**What to verify:** The NTP property is `yes` or `no` when supported.

### Worked example 3: Ask chrony for sources

```bash
chronyc sources -v
```

**Line-by-line explanation:**

1. `chronyc` queries chronyd; `sources -v` shows detailed time sources and selection marks.

**What to verify:** A leading `^*` marks the currently selected network source.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 108.2 System logging

### What this objective teaches

Query the journal, understand syslog facility and priority, create test records, and rotate files.

### Worked example 1: Create a test record

```bash
logger -p user.notice -t lpic-lab 'logging works'
```

**Line-by-line explanation:**

1. `logger` sends a record; `-p` sets facility and priority, `-t` sets the tag, and the final argument is the message.

**What to verify:** The record goes to the configured journal or syslog path.

### Worked example 2: Find the test record

```bash
journalctl -t lpic-lab --since '5 minutes ago'
```

**Line-by-line explanation:**

1. `journalctl -t` filters by tag and `--since` limits the time window.

**What to verify:** The message `logging works` should appear if the journal received it.

### Worked example 3: Check log rotation

```bash
sudo logrotate --debug /etc/logrotate.conf
```

**Line-by-line explanation:**

1. `logrotate --debug` reads configuration and explains planned actions without rotating files; `sudo` lets it inspect protected paths.

**What to verify:** Review the plan and errors; debug mode makes no log changes.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 108.3 Mail transfer agent basics

### What this objective teaches

Recognize local mail submission, aliases, forwarding, queues, and common MTAs.

### Worked example 1: Inspect aliases

```bash
grep -Ev '^[[:space:]]*(#|$)' /etc/aliases
```

**Line-by-line explanation:**

1. `grep -E` uses extended regex and `-v` removes comments and blank lines from the aliases file.

**What to verify:** A typical file maps names such as `postmaster` to a local administrator.

### Worked example 2: Read the queue

```bash
mailq
```

**Line-by-line explanation:**

1. `mailq` asks the installed MTA compatibility interface to list queued messages.

**What to verify:** An empty queue is healthy; the command may be absent when no MTA is installed.

### Worked example 3: Check user forwarding

```bash
test -f "$HOME/.forward" && sed -n '1,20p' "$HOME/.forward" || echo 'no .forward file'
```

**Line-by-line explanation:**

1. `test` checks for the file, `&&` prints its first 20 lines on success, and `||` prints a fallback when the chain fails.

**What to verify:** Review forwarding destinations carefully because loops and command pipes can be dangerous.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.

## 108.4 Printing

### What this objective teaches

Understand CUPS queues, default destinations, jobs, submission, and cancellation.

### Worked example 1: Read printer status

```bash
lpstat -t
```

**Line-by-line explanation:**

1. `lpstat -t` prints a broad summary of the CUPS server, default destination, queues, and jobs.

**What to verify:** It may report that no destinations exist on a machine without printers.

### Worked example 2: List queued jobs

```bash
lpq -a
```

**Line-by-line explanation:**

1. `lpq` shows print jobs; `-a` requests all configured queues.

**What to verify:** Queued job IDs are needed for targeted cancellation.

### Worked example 3: Inspect CUPS service

```bash
systemctl status cups.service --no-pager
```

**Line-by-line explanation:**

1. `systemctl status` reports the CUPS unit and recent logs; `--no-pager` prints directly.

**What to verify:** Some distributions name the unit differently or do not install CUPS.

### Common mistakes and troubleshooting

Do not copy a device name, account name, service name, or path without checking that it exists on your machine. A command that prints nothing may have found no matches; check its exit status with `printf 'status=%s\n' "$?"`. Read permission errors instead of hiding them, and use `man COMMAND` before adding an unfamiliar write or delete option.
