# 106 — محیط گرافیکی و دسترس‌پذیری

[فهرست دوره](README.md)

**پیش‌نیاز:** فصل صفر؛ این تمرین‌ها در VM دارای دسکتاپ انجام می‌شوند

مثال‌ها را به ترتیب هر درس در همان ترمینال اجرا کنید. «خروجی نمونه» عین خروجی همهٔ دستگاه‌ها نیست؛ نام‌ها، شماره‌ها و نسخه‌ها ممکن است فرق کنند. بلوک `text` داده یا پاسخ تعاملی است و نباید به‌عنوان دستور Bash اجرا شود.

## 106.1 — X11، Wayland و صفحهٔ ورود

### مفهوم و کاربرد

در X11 «سرور» کنار صفحه و صفحه‌کلید کاربر است و برنامه‌ها client هستند؛ سرور خدمت نمایش و ورودی می‌دهد. Display manager صفحهٔ ورود مثل GDM/SDDM/LightDM است. Window manager محل و قاب پنجره و desktop environment مجموعهٔ یکپارچهٔ ابزارهای محیط کار است.

Wayland پروتکل دیگری است که compositor نقش نمایش و ترکیب پنجره را بر عهده دارد. XWayland کمک می‌کند برنامهٔ X11 داخل نشست Wayland اجرا شود. وجود DISPLAY به‌تنهایی ثابت نمی‌کند نشست اصلی X11 است.

### مثال 1: شناخت نشست

دستورها را از ترمینال داخل دسکتاپ اجرا کنید، نه SSH.

```bash
printf 'type=%s
' "${XDG_SESSION_TYPE:-unknown}"
printf 'display=%s
' "${DISPLAY:-unset}"
loginctl list-sessions
```

**توضیح خط‌به‌خط:**

1. نوع نشست، معمولاً x11 یا wayland؛ اگر متغیر نیست unknown.
2. نشانی X server را می‌خواند؛ نمونه :0 یا :1.
3. نشست‌های ثبت‌شدهٔ logind را فهرست می‌کند.

**نتیجه و بررسی:** DISPLAY با قالب host:display.screen است؛ :0 یعنی نمایش محلی صفر. متغیر محیط یک سرنخ است؛ با نوع نشست و برنامه‌های فعال مقایسه کنید.

### مثال 2: خواندن تنظیم صفحه‌کلید Xorg

صرفاً یک فایل نمونه برای فهم؛ آن را بدون نیاز در /etc نصب نکنید.

```text
Section "InputClass"
    Identifier "lpic-keyboard"
    MatchIsKeyboard "on"
    Option "XkbLayout" "us"
EndSection
```

**توضیح خط‌به‌خط:**

1. شروع بخش قانون گروه ورودی.
2. نام این قانون برای شناسایی در تنظیم/گزارش.
3. فقط دستگاه‌هایی که صفحه‌کلید هستند مطابق‌اند.
4. طرح صفحه‌کلید انگلیسی آمریکا برای دستگاه‌های منطبق.
5. پایان بخش.

**نتیجه و بررسی:** فایل‌های override معمولاً /etc/X11/xorg.conf.d/*.conf و تنظیم یکپارچه /etc/X11/xorg.conf است. روی Wayland، تنظیم compositor ممکن است مسیر دیگری داشته باشد.

### مثال 3: کنترل دسترسی و گزارش

در همان نشست گرافیکی؛ کوکی X11 محرمانه است.

```bash
xhost
xauth info
systemctl status display-manager.service --no-pager
journalctl -b --no-pager | grep -Ei 'xorg|wayland|display-manager'
```

**توضیح خط‌به‌خط:**

1. بدون آرگومان وضعیت access control را می‌خواند؛ xhost + اجرا نمی‌کنیم.
2. اطلاعات فایل و تعداد entry را می‌دهد، بدون چاپ مقدار کوکی‌ها.
3. وضعیت display manager را از alias رایج سرویس می‌خواند.
4. گزارش همین بوت با جست‌وجوی ERE و بی‌توجهی به بزرگی حروف محدود می‌شود.

**نتیجه و بررسی:** فایل ~/.xsession-errors روی همهٔ دسکتاپ‌ها وجود ندارد. فقدان آن به‌معنی نبود هیچ خطا نیست.

### اشتباه رایج و عیب‌یابی

برای رفع Cannot open display از xhost + استفاده نکنید؛ نشست، DISPLAY و مجوز را بررسی کنید. SSH عادی الزاماً نمایش گرافیکی نمی‌سازد.

### نکته‌های تکمیلی این سرفصل

برای آماده‌سازی در Debian آزمایش، `sudo apt install xorg xauth x11-apps` اجزای X و ابزار تست را نصب می‌کند؛ اگر desktop کامل می‌خواهید مسیر نصب فصل صفر را دنبال کنید. برای اجرای دوردست، کلاینت باید X server داشته باشد، سرور sshd اجازهٔ X11Forwarding بدهد و xauth موجود باشد. `ssh -X USER@HOST` انتقال X11 غیرtrusted را درخواست می‌کند و سپس برنامه‌ای مثل xclock روی میزبان دوردست اجرا می‌شود. `-Y` trusted است و به برنامهٔ دوردست اعتماد بیشتری می‌دهد؛ فقط میزبان مورد اعتماد. USER/HOST واقعی محیط آزمایش را جایگزین کنید. `xauth list` خود کوکی را نشان می‌دهد؛ آن را در گزارش عمومی نگذارید.

### تمرین مستقل

اگر برنامه روی سرور اجرا و پنجره روی لپ‌تاپ تو نمایش داده شود در اصطلاح X11 کدام طرف server است؟

## 106.2 — انتخاب دسکتاپ و دسترسی دوردست

### مفهوم و کاربرد

GNOME، KDE Plasma و Xfce سه محیط رایج‌اند. تفاوتشان فقط ظاهر نیست؛ ابزار تنظیم، برنامه‌ها، مصرف منابع و تجربهٔ کار فرق می‌کند. Window manager جزئی از این تجربه است و display manager ورود به آن را آغاز می‌کند.

VNC نمایش دسکتاپ با RFB، RDP پروتکل Remote Desktop، SPICE رایج در کنسول VM، X11 forwarding برای برنامه‌های تکی و XDMCP ورود گرافیکی شبکه‌ای قدیمی است. رمزگذاری و احراز هویت هر پیاده‌سازی را باید مستقل سنجید.

### مثال 1: شناخت محیط فعلی

ترمینال داخل دسکتاپ.

```bash
printf '%s
' "${XDG_CURRENT_DESKTOP:-unknown}"
printf '%s
' "${DESKTOP_SESSION:-unknown}"
```

**توضیح خط‌به‌خط:**

1. نام محیط اعلام‌شده را می‌خواند.
2. نام نشست انتخاب‌شده را می‌خواند.

**نتیجه و بررسی:** ممکن است مقدار شامل چند نام با دونقطه باشد؛ وجود واژه GNOME یا KDE را با صفحهٔ About محیط مقایسه کنید.

### مثال 2: انتخاب برای یک برنامه

سناریوی تحلیلی؛ دستور نیست.

```text
Need: one trusted remote graphical program
Choice: SSH X11 forwarding
Check: local display and remote forwarding policy
```

**توضیح خط‌به‌خط:**

1. نیاز فقط نمایش یک برنامه است، نه کنترل کامل desktop.
2. در صورت پشتیبانی دو طرف می‌توان از انتقال X11 رمز‌شدهٔ SSH استفاده کرد.
3. وجود نمایش محلی، xauth و سیاست سرور را بررسی می‌کنیم.

**نتیجه و بررسی:** انتخاب به پشتیبانی برنامه و شرایط شبکه وابسته است؛ X11 forwarding برای هر برنامهٔ Wayland جایگزین عمومی نیست.

### مثال 3: انتخاب برای کنسول یا دسکتاپ کامل

سناریوی تحلیلی.

```text
VM console: SPICE
Full remote session: RDP or VNC
Legacy login: XDMCP
```

**توضیح خط‌به‌خط:**

1. برای VM با stack پشتیبان SPICE، دیدن صفحهٔ boot و نشست مهمان مناسب است.
2. برای دسکتاپ کامل بسته به server/client موجود از RDP یا VNC استفاده می‌کنیم.
3. شناخت آزمونی مهم است؛ بدون حفاظت مناسب روی شبکهٔ نامطمئن مناسب نیست.

**نتیجه و بررسی:** کنسول hypervisor می‌تواند وقتی شبکهٔ مهمان قطع است کمک کند؛ سرویس RDP داخل همان مهمان معمولاً به شبکهٔ مهمان نیاز دارد.

### اشتباه رایج و عیب‌یابی

شمارهٔ پورت یا نام پروتکل به‌تنهایی تضمین encryption نیست. VNC را بدون حفاظت روی همهٔ interfaceها منتشر نکنید.

### تمرین مستقل

برای VM که تنظیم شبکه‌اش خراب شده، کنسول مجازی بهتر است یا SSH به همان IP؟

## 106.3 — دسترس‌پذیری برای کاربران متفاوت

### مفهوم و کاربرد

دسترس‌پذیری یعنی فرد با نیاز بینایی، شنوایی یا حرکتی بتواند کار واقعی‌اش را انجام دهد. Screen reader متن/کنترل را صوتی می‌خواند؛ Braille display خروجی لمسی، magnifier بزرگ‌نمایی بخش صفحه و high contrast تفاوت رنگ‌ها را بیشتر می‌کند. بزرگ‌کردن فونت با بزرگ‌کردن کل صفحه یک چیز نیست.

Sticky keys ترکیب کلیدها را پشت‌سرهم ممکن می‌کند؛ slow keys ثبت پس از نگه‌داشتن، bounce keys حذف فشارهای جداگانهٔ خیلی نزدیک و repeat keys رفتار تکرار هنگام نگه‌داشتن کلید است. Toggle keys تغییر حالت‌هایی مثل Caps Lock را خبر می‌دهد.

### مثال 1: بزرگ‌نمایی و contrast

تمرین عملی در Settings؛ نام منو با محیط و زبان فرق دارد.

```text
Settings → Accessibility → Seeing
Large Text / High Contrast
Restore previous setting
```

**توضیح خط‌به‌خط:**

1. بخش دیداری را پیدا کنید؛ تنظیم قبلی را یادداشت کنید.
2. یکی را فعال کنید و یک پنجرهٔ متن بخوانید تا اثر را بسنجید.
3. مقدار قبل را بازگردانید؛ فقط بزرگ‌ترشدن تصویر معیار موفقیت نیست، خواندن باید راحت‌تر شود.

**نتیجه و بررسی:** کاربر باید بتواند متن و کنترل‌ها را بخواند بدون پنهان‌شدن دکمه‌های لازم.

### مثال 2: تمرین sticky و bounce

در یک ویرایشگر با فایل آزمایشی؛ نه پنجرهٔ رمز.

```text
Enable Sticky Keys
Compare Repeat and Bounce settings
Restore keyboard settings
```

**توضیح خط‌به‌خط:**

1. Sticky را فعال کنید، Shift را رها و سپس یک حرف بزنید؛ نیاز به نگه‌داری همزمان کم می‌شود.
2. نگه‌داشتن یک کلید را با دو فشار سریع جدا مقایسه کنید؛ اولی Repeat و دومی Bounce است.
3. تمام تنظیم‌های تغییرکرده را به قبل برگردانید.

**نتیجه و بررسی:** اگر حرف‌ها ظاهراً گم می‌شوند ممکن است Slow/Bounce فعال باشد، نه خرابی صفحه‌کلید.

### مثال 3: خروجی صوتی و ورودی جایگزین

بخش Accessibility محیط خودتان.

```text
Screen Reader
On-Screen Keyboard / Mouse Keys
Login screen check
```

**توضیح خط‌به‌خط:**

1. در یک متن آزمایش screen reader را فعال و حرکت focus را بررسی کنید؛ صدای خروجی باید قابل شنیدن باشد.
2. صفحه‌کلید روی صفحه برای کلیک، و Mouse Keys برای حرکت نشانگر با کلیدها را مقایسه کنید.
3. بررسی کنید قابلیت لازم در صفحهٔ ورود هم قابل استفاده است؛ تنظیم نشست همیشه به login منتقل نمی‌شود.

**نتیجه و بررسی:** Braille سخت‌افزار پشتیبان می‌خواهد؛ gestures و voice recognition هم ورودی جایگزین‌اند و وابستگی به محیط/زبان دارند.

### اشتباه رایج و عیب‌یابی

برای همهٔ افراد یک تنظیم اجباری اعمال نکنید. feature باید با کاربر و نرم‌افزار مورد استفاده سنجیده شود.

### تمرین مستقل

کسی هنگام نگه‌داشتن کلید با تکرار زیاد مشکل دارد. Bounce یا Repeat را اول بررسی می‌کنید؟
