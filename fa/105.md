## 105.1 — تنظیم محیط و تابع

### مفهوم و کاربرد

محیط shell شامل متغیر، alias، تابع و گزینه‌هاست. Login shell معمولاً /etc/profile و نخستین فایل خواندنی از .bash_profile، .bash_login، .profile را می‌خواند. Interactive non-login Bash معمولاً .bashrc را می‌خواند. Login لزوماً .bashrc را خودکار نمی‌خواند؛ فایل profile می‌تواند آن را source کند.

`source FILE` یا `. FILE` کد را داخل همین shell اجرا می‌کند؛ `bash FILE` فرزند می‌سازد. فقط فایل شناخته‌شده را source کنید، چون کد است، نه صرفاً داده.

### مثال 1: تفاوت اجرا و source

در پوشهٔ موقت؛ فقط متغیر تمرین را تغییر می‌دهیم.

```bash
shell_lab=$(mktemp -d)
printf 'LPIC_LEVEL=beginner
' > "$shell_lab/settings.sh"
bash "$shell_lab/settings.sh"
printf '%s
' "${LPIC_LEVEL:-unset}"
. "$shell_lab/settings.sh"
printf '%s
' "$LPIC_LEVEL"
```

**توضیح خط‌به‌خط:**

1. محیط فایل مستقل می‌سازد.
2. یک فایل با یک انتساب می‌سازد؛ printf فقط سازندهٔ فایل است.
3. فرزند فایل را اجرا می‌کند؛ مقدار در والد باقی نمی‌ماند.
4. unset انتظار می‌رود، مگر پیش‌تر همین متغیر را در والد ساخته باشید.
5. نقطه اجرای فایل در shell فعلی است.
6. اکنون beginner چاپ می‌شود.

**نتیجه و بررسی:** با `unset LPIC_LEVEL` مقدار آزمایش را پاک کنید. فایل sourceشده می‌تواند cd و export هم انجام دهد.

### مثال 2: تابع دارای آرگومان

تعریف چندخطی را در Bash وارد کنید.

```bash
mkcd() {
    mkdir -p -- "$1" && cd -- "$1"
}
mkcd "$shell_lab/two words"
pwd
```

**توضیح خط‌به‌خط:**

1. تابع با نام mkcd شروع می‌شود؛ () بخش اعلان تابع است.
2. $1 ورودی اول؛ mkdir با p والد می‌سازد و -- پایان گزینه‌هاست؛ cd تنها پس از موفقیت mkdir اجرا می‌شود.
3. پایان تعریف؛ هنوز بدنه اجرا نشده است.
4. تابع با یک مسیر دارای فاصله صدا زده می‌شود.
5. باید مسیر پوشهٔ تازه را نشان دهد.

**نتیجه و بررسی:** تابع داخل همین shell اجرا می‌شود، پس cd ماندگار است. alias برای میان‌بر ساده مثل `alias ll='ls -alF'` مناسب است؛ تابع ورودی و منطق دارد.

### مثال 3: بررسی فایل‌های آغاز

فقط می‌خوانیم؛ فایل تنظیم اصلی را بازنویسی نمی‌کنیم.

```bash
ls -la "$HOME/.bashrc" "$HOME/.profile"
ls -la /etc/skel
bash --noprofile --norc -c "printf clean-shell\n"
```

**توضیح خط‌به‌خط:**

1. وجود و مجوز دو فایل معمول را می‌سنجد؛ نبود یکی روی بعضی توزیع‌ها طبیعی است.
2. فایل‌های الگوی home کاربر جدید را می‌خواند؛ a فایل‌های نقطه‌دار را هم نشان می‌دهد.
3. Bash بدون profile و rc برای اجرای آزمایشی جدا اجرا می‌شود؛ این فقط نمایش نحوهٔ انتخاب startup است.

**نتیجه و بررسی:** تغییر /etc/skel فقط روی homeهایی اثر دارد که بعداً با کپی skeleton ساخته می‌شوند؛ home کاربران قبلی خودکار تغییر نمی‌کند.

### اشتباه رایج و عیب‌یابی

اضافه‌کردن نقطه یا پوشهٔ قابل‌نوشتن دیگران به ابتدای PATH راه اجرای دستور جعلی را باز می‌کند. پیش از source فایل ناشناس، آن را بخوانید.

### نکته‌های تکمیلی این سرفصل

برای افزودن مسیر شخصی، `PATH="$HOME/bin:$PATH"` مقدار قبلی را حفظ و مسیر جدید را ابتدا می‌گذارد؛ `export PATH` آن را صادر می‌کند. این دو را بدون کنترل تکرار مدام به .bashrc اضافه نکنید. روش جلوگیری از تکرار: در `case ":$PATH:" in` الگوی `*":$HOME/bin:"*) ;;` یعنی اگر موجود است هیچ؛ شاخهٔ `*) PATH="$HOME/bin:$PATH" ;;` یعنی اگر نیست اضافه؛ `esac` پایان انتخاب و سپس export. دو‌نقطه‌های ابتدا/انتها مرز یک مسیر را کامل می‌کنند.

`/etc/bash.bashrc` در Debian و `/etc/bashrc` در بعضی RPMها تنظیم عمومی تعاملی‌اند؛ نحوهٔ خواندن به بستهٔ Bash و profileها وابسته است. .bash_logout هنگام خروج login shell استفاده می‌شود. `set` متغیر و تابع، `env` محیط صادرشده، `export` انتقال به فرزند و `unset` حذف است. برای حذف alias از `unalias ll` و برای حذف تابع از `unset -f mkcd` استفاده کنید.

## 105.2 — نوشتن اسکریپت با منطق و خطا

### مفهوم و کاربرد

اسکریپت فایل متنِ دستورهاست که interpreter می‌خواند. shebang خط اول با #! تعیین می‌کند در اجرای مستقیم کدام interpreter استفاده شود. Bash امکانات بیشتری از sh استاندارد دارد؛ اگر از قابلیت خاص Bash استفاده می‌کنید همان را انتخاب کنید. در این درس فایل‌ها را با vi در پوشهٔ تمرین بسازید؛ خط شمارهٔ توضیحات جزو کد نیست.

`$0` نام فراخوانی، `$1` ورودی اول، `${10}` ورودی دهم، `$#` تعداد، `"$@"` همهٔ ورودی‌ها با حفظ مرز، `$?` نتیجهٔ قبلی و `$$` PID shell است. status صفر موفقیت قراردادی و غیرصفر وضعیت دیگر/خطاست.

### مثال 1: اسکریپت سلام

فایل hello.sh را با همین محتوا بسازید.

```bash
#!/bin/bash
name=${1:-world}
printf 'Hello, %s
' "$name"
```

**توضیح خط‌به‌خط:**

1. shebang مفسر ثابت Bash را انتخاب می‌کند؛ مسیر باید در VM موجود باشد.
2. اگر ورودی اول نیست یا خالی است world، وگرنه همان ورودی را می‌گیرد.
3. قالب ثابت است و مقدار با نقل‌قول یک آرگومان می‌ماند.

**نتیجه و بررسی:** در shell `bash -n hello.sh` نحو را بررسی می‌کند؛ `chmod 750 hello.sh` اجازهٔ اجرا و `./hello.sh "Sara Ahmadi"` متن Hello, Sara Ahmadi می‌دهد؛ بدون ورودی Hello, world.

### مثال 2: پذیرش تنها یک فایل معتبر

فایل count-lines.sh؛ فاصله‌های داخل [ ] مهم‌اند.

```bash
#!/bin/bash
if [ "$#" -ne 1 ]; then
    printf 'Usage: %s FILE
' "$0" >&2
    exit 2
fi
if [ -f "$1" ] && [ -r "$1" ]; then
    wc -l < "$1"
else
    printf 'Not a readable regular file: %s
' "$1" >&2
    exit 1
fi
```

**توضیح خط‌به‌خط:**

1. interpreter همین فایل است.
2. اگر تعداد آرگومان‌ها برابر یک نیست، شاخهٔ خطا اجرا شود؛ -ne مقایسهٔ عددی نابرابری است.
3. راهنمای استفاده را روی stderr می‌نویسد؛ >&2 خروجی به descriptor خطاست.
4. اسکریپت را با کد 2، قراردادی برای ورودی غلط، تمام می‌کند.
5. پایان شرط اول.
6. دو آزمون AND: فایل عادی هست و برای کاربر فعلی قابل خواندن است.
7. سطرهای فایل را با stdin می‌شمارد؛ اگر wc خطا دهد status آن باقی می‌ماند.
8. در غیر این صورت شاخهٔ خطا.
9. علت را با نام فایل چاپ می‌کند.
10. خروج ناموفق.
11. پایان شرط؛ در مسیر موفق نتیجهٔ wc نتیجهٔ نهایی است.

**نتیجه و بررسی:** یک sample با `printf 'a\nb\n' > sample.txt` بسازید. `bash count-lines.sh sample.txt` باید 2 بدهد؛ بدون ورودی کد 2 و با مسیر گمشده کد 1. بلافاصله پس از هر اجرا `printf "%s\n" "$?"` بزنید.

### مثال 3: حلقه روی ورودی‌ها

فایل list-inputs.sh؛ روی هر ورودی فقط گزارش می‌دهد.

```bash
#!/bin/bash
for item in "$@"; do
    if [ -f "$item" ]; then
        printf 'file: %s
' "$item"
    else
        printf 'not-file: %s
' "$item"
    fi
done
```

**توضیح خط‌به‌خط:**

1. Bash.
2. هر آرگومان اصلی، حتی دارای فاصله، یک بار به item می‌رود.
3. اگر آن ورودی فایل عادی است.
4. نام را همراه برچسب file چاپ می‌کند.
5. شاخهٔ دیگر.
6. برای پوشه یا مسیر گمشده گزارش متفاوت می‌دهد.
7. پایان شرط درون حلقه.
8. پایان تکرار؛ این اسکریپت گزارش است و نبود فایل را failure کلی تعریف نکرده است.

**نتیجه و بررسی:** با `bash list-inputs.sh sample.txt "missing name" .` سه گزارش مستقل می‌گیرید. نقطه پوشه است و not-file می‌شود.

### مثال 4: while و گرفتن ورودی

فایل repeat.sh؛ تعاملی است.

```bash
#!/bin/bash
printf 'Enter a word: '
IFS= read -r word
count=1
while [ "$count" -le 3 ]; do
    printf '%s: %s
' "$count" "$word"
    count=$((count + 1))
done
```

**توضیح خط‌به‌خط:**

1. انتخاب Bash.
2. پیام بدون newline برای ورود کاربر.
3. read یک خط می‌خواند؛ IFS خالی حفظ فاصلهٔ کناره‌ها و r حفظ backslash است.
4. شمارنده از یک شروع می‌شود.
5. تا وقتی شمارنده کوچک‌تر یا برابر سه است.
6. شماره و متن را چاپ می‌کند.
7. حساب عددی shell و افزایش شمارنده؛ بدون این خط حلقه تمام نمی‌شود.
8. پایان حلقه.

**نتیجه و بررسی:** پس از `bash repeat.sh` واژهٔ Linux و Enter بدهید؛ سه خط شماره‌دار خواهید دید. Ctrl+D ورودی EOF است؛ این مثال ساده آن را جدا مدیریت نمی‌کند، در script واقعی status read را بررسی کنید.

### اشتباه رایج و عیب‌یابی

بدنهٔ script را با sh اجرا نکنید اگر Bash-specific است. `bash -n` فقط نحو را می‌سنجد، نه درست‌بودن مسیرها/نتیجه. `set -e` راه جادویی خطایابی نیست و استثناهای زمینه‌ای دارد.

### نکته‌های تکمیلی این سرفصل

| ساختار | معنی و نمونه |
|---|---|
| `test -d PATH` یا `[ -d PATH ]` | پوشه بودن؛ -e وجود، -f فایل، -r خواندنی، -w نوشتنی، -x قابل اجرا/عبور |
| `[ -z "$v" ]` | رشته خالی؛ `[ "$a" = "$b" ]` برابری متن |
| -eq، -ne، -lt، -le، -gt، -ge | برابر، نابرابر، کوچک‌تر، کوچک‌تر/مساوی، بزرگ‌تر، بزرگ‌تر/مساوی اعداد |
| `seq 1 3` | چاپ 1 تا 3 هرکدام در یک خط |
| `kernel=$(uname -r)` | گرفتن خروجی برنامه؛ سپس با printf و نقل‌قول نمایش دهید |
| `A && B` | B فقط پس از موفقیت A؛ `A \|\| B` فقط پس از ناموفق‌بودن A |
| `case "$1" in start) echo start ;; *) echo other ;; esac` | انتخاب بر اساس glob؛ ;; پایان شاخه و esac پایان انتخاب |
| `exec /usr/bin/printf 'done\n'` | جایگزینی shell با برنامه؛ خط‌های بعد در آن shell اجرا نمی‌شوند |
| `set -o nounset` | ارجاع تصادفی به متغیر تعریف‌نشده خطا می‌دهد؛ مقدار پیش‌فرض را آگاهانه استفاده کنید |
| `set -o pipefail` | نتیجهٔ pipeline در Bash به خطای میانی هم حساس می‌شود |

برای اطلاع محلیِ شکست به مدیر، شرط `if ! tar -czf backup.tar.gz data; then` را با `printf 'backup failed\n' \| mail -s 'LPIC backup' root` و `fi` کامل کنید: ! وضعیت را وارونه، then مسیر خطا، mail گیرندهٔ محلی root را انتخاب می‌کند. این فقط با MTA محلی آماده کار می‌کند؛ نبود mail را هم باید مدیریت کرد. نسخهٔ اجراشدنی گزارش سیستم و تست ورودی‌ها در [آزمایشگاه تکمیلی](labs.md) است.

script مدیریتی محلی می‌تواند زیر /usr/local/sbin با مالک root و mode 0750 نصب شود؛ هیچ مسیر قابل‌نوشتن کاربر نامطمئن نباید در زنجیرهٔ آن باشد. Linux معمولاً SUID script را اعمال نمی‌کند؛ برای امتیاز از sudo محدود استفاده کنید. `shellcheck FILE` در صورت نصب، خطاهای محتمل shell را علاوه بر نحو بررسی می‌کند.
