# 103 — کار با خط فرمان، فایل، متن و پردازه

[فهرست دوره](README.md)

**پیش‌نیاز:** فصل صفر؛ مثال‌های هر درس را در پوشهٔ جدا و به ترتیب اجرا کنید

مثال‌ها را به ترتیب هر درس در همان ترمینال اجرا کنید. «خروجی نمونه» عین خروجی همهٔ دستگاه‌ها نیست؛ نام‌ها، شماره‌ها و نسخه‌ها ممکن است فرق کنند. بلوک `text` داده یا پاسخ تعاملی است و نباید به‌عنوان دستور Bash اجرا شود.

## 103.1 — دستور، آرگومان، نقل‌قول و محیط

### مفهوم و کاربرد

ترمینال پنجرهٔ ورود و نمایش متن است؛ shell مانند Bash متن را تفسیر و برنامه را اجرا می‌کند. در `ls -l /etc`، نام دستور ls، گزینهٔ رفتاری -l و موضوع کار /etc است. فاصله آرگومان‌ها را جدا می‌کند. نام و گزینه‌ها به بزرگی حروف حساس‌اند.

متغیر نامی برای نگه‌داری مقدار است. در انتساب پیرامون `=` فاصله نداریم. `$name` مقدار را می‌خواند. نقل‌قول تکی محتوا را عیناً و دوتایی با امکان بازشدن متغیر نگه می‌دارد. shell قبل از اجرای برنامه expansion و redirection را انجام می‌دهد.

### مثال 1: دیدن تفاوت نقل‌قول

در Bash معمولی، بدون sudo.

```bash
student='Sara Ahmadi'
printf '%s
' "$student"
printf '%s
' '$student'
```

**توضیح خط‌به‌خط:**

1. یک مقدار دارای فاصله در متغیر student قرار می‌گیرد؛ تکی‌ها جزو مقدار نیستند.
2. printf به‌جای %s مقدار student و به‌جای \n خط جدید می‌نویسد. دوتایی از دو آرگومان‌شدن نام جلوگیری می‌کند.
3. تکی‌ها مانع گسترش متغیر می‌شوند؛ خود $student چاپ می‌شود.

**نتیجه و بررسی:** خط دوم `Sara Ahmadi` و خط سوم `$student` است. `echo` برای متن ساده قابل استفاده است ولی رفتار -n و escapeهای آن بین shellها فرق دارد.

### مثال 2: ارث‌بری محیط

فقط متغیر آزمایشی می‌سازیم؛ کل env را در گزارش عمومی نریزید.

```bash
LPIC_COLOR=blue
bash -c 'printf "%s\n" "${LPIC_COLOR:-unset}"'
export LPIC_COLOR
bash -c 'printf "%s\n" "$LPIC_COLOR"'
unset LPIC_COLOR
```

**توضیح خط‌به‌خط:**

1. متغیر محلی shell است.
2. Bash فرزند یک رشتهٔ دستور با -c اجرا می‌کند؛ :-unset وقتی مقدار نیست یا خالی است متن unset می‌دهد.
3. متغیر برای فرزندهای بعدی صادر می‌شود.
4. فرزند جدید مقدار صادرشده را می‌بیند.
5. متغیر از shell فعلی پاک می‌شود.

**نتیجه و بررسی:** ابتدا unset و بعد blue چاپ می‌شود. فرزند نمی‌تواند متغیر والد را مستقیماً عوض کند.

### مثال 3: پیداکردن دستور و راهنما

بدون تغییر PATH.

```bash
type cd
type -a ls
printf '%s
' "$PATH" | tr ':' '
'
man 1 passwd
man 5 passwd
```

**توضیح خط‌به‌خط:**

1. نشان می‌دهد cd یک builtin است؛ باید پوشهٔ خود shell را تغییر دهد.
2. همهٔ تشخیص‌های ls، مانند alias و executable، را نشان می‌دهد.
3. PATH مسیرهای جست‌وجوست؛ pipe خروجی را به tr می‌دهد و tr دونقطه‌ها را به خط جدید تبدیل می‌کند.
4. راهنمای فرمان passwd از بخش 1؛ با q خارج شوید.
5. راهنمای قالب فایل passwd از بخش 5، نه دستور تغییر رمز.

**نتیجه و بررسی:** PATH با مسیر فعلی فرق دارد. `./script.sh` صریحاً برنامهٔ پوشهٔ فعلی است. `which ls` معمولاً executable را می‌یابد ولی برای builtin قابل اتکا نیست.

### اشتباه رایج و عیب‌یابی

`name = value` انتساب نیست؛ shell دنبال دستور name می‌گردد. `sudo` درمان command not found نیست. ابتدا نام، نصب و PATH را بررسی کنید.

### نکته‌های تکمیلی این سرفصل

`pwd` پوشهٔ فعلی، `uname -a` اطلاعات kernel و معماری، `history 10` ده دستور آخر و `~/.bash_history` فایل رایج تاریخچه است. در shell تعاملی `!!` قبلی و `!42` ورودی 42 را دوباره اجرا می‌کند؛ نخست با ↑ یا Ctrl+R متن را ببینید. رازها را در history ننویسید. `set` متغیرها و توابع shell، `env` محیط صادرشده و `unset NAME` حذف را انجام می‌دهند.

`mkdir -p demo && cd demo`: p ساخت والدهای لازم، && اجرای cd فقط پس از موفقیت است. `test -f note || touch note`: اگر فایل عادی نیست، touch اجرا می‌شود. `;` اجرای بعدی را مستقل از موفقیت قبلی انجام می‌دهد. `false; printf ...` همچنان printf را اجرا می‌کند. backslash بیرون نقل‌قول می‌تواند نویسهٔ بعدی را literal کند. برای نامی با فاصله مثل `my notes.txt` از نقل‌قول استفاده کنید.

### تمرین مستقل

خروجی `n=5` سپس `printf "%s
" "$n"` و `printf "%s
" '$n'` چیست؟

اولی 5 و دومی متن $n است؛ در تکی substitution رخ نمی‌دهد.

</details>

## 103.2 — خواندن و پردازش متن

### مفهوم و کاربرد

بیشتر ابزارهای Unix یک کار کوچک روی جریان متن انجام می‌دهند. خروجی یکی را می‌توان ورودی دیگری کرد. فایل‌ها را اول خودمان می‌سازیم تا دنبال فایل خیالی نباشیم. فیلتر معمولاً فایل اصلی را تغییر نمی‌دهد مگر خروجی را خودتان روی آن بنویسید.

فرق مهم: `sort` سطرها را مرتب می‌کند؛ `uniq` فقط تکرارهای کنارهم را می‌بیند. `cut` ستون را بر مبنای جداکننده می‌برد و یک parser کامل CSV دارای نقل‌قول نیست.

### مثال 1: ورودی مشخص، خروجی مشخص

یک پوشهٔ اختصاصی برای این درس بسازید.

```bash
text_lab=$(mktemp -d)
cd "$text_lab"
printf 'sara,ops
ali,dev
sara,ops
' > people.csv
cat people.csv
nl -ba people.csv
head -n 2 people.csv
tail -n 1 people.csv
```

**توضیح خط‌به‌خط:**

1. پوشهٔ یکتا می‌سازد؛ مسیر برای ادامه در متغیر می‌ماند.
2. به همان پوشه می‌رویم.
3. سه سطر داده می‌سازد؛ > فایل را می‌سازد یا محتوای قبلی را جایگزین می‌کند.
4. همهٔ متن را می‌خواند.
5. nl شماره‌گذاری می‌کند؛ -b a یعنی همهٔ خط‌ها، حتی خالی‌ها.
6. دو خط اول را می‌دهد.
7. یک خط آخر را می‌دهد.

**نتیجه و بررسی:** سه خط sara,ops سپس ali,dev و sara,ops داریم. tail فقط sara,ops می‌دهد. `less people.csv` با / جست‌وجو، n تکرار و q خروج دارد.

### مثال 2: گزارش تعداد نقش‌ها

در همان پوشه و بعد از مثال اول.

```bash
cut -d, -f2 people.csv
cut -d, -f2 people.csv | sort | uniq -c
wc -l -w -c people.csv
tr '[:lower:]' '[:upper:]' < people.csv
```

**توضیح خط‌به‌خط:**

1. `-d,` جداکنندهٔ ویرگول و `-f2` ستون دوم یعنی نقش است.
2. نقش‌ها مرتب و تکرارهای مجاور با -c شمرده می‌شوند.
3. تعداد newline، واژه و بایت را می‌دهد؛ -c تعداد نویسهٔ Unicode نیست.
4. با < فایل به stdin داده می‌شود؛ tr حروف کوچک را بزرگ می‌کند.

**نتیجه و بررسی:** گزارش نقش‌ها شامل `1 dev` و `2 ops` است؛ فاصله‌های ابتدای خروجی uniq طبیعی‌اند. wc برای این ورودی 3 خط، 3 واژه و 26 بایت می‌دهد.

### مثال 3: چسباندن، تقسیم و صحت

در همان پوشه.

```bash
printf 'Sara
Ali
' > names.txt
printf 'ops
dev
' > roles.txt
paste names.txt roles.txt
split -l 2 people.csv part-
cat part-* > rebuilt.csv
sha256sum people.csv rebuilt.csv
```

**توضیح خط‌به‌خط:**

1. دو نام را می‌سازد.
2. دو نقش هم‌ترتیب را می‌سازد.
3. خط‌های هم‌شماره را با tab کنارهم می‌گذارد؛ اتصال مبتنی بر کلید نیست.
4. هر قطعه حداکثر دو خط؛ نام‌ها part-aa و part-ab می‌شوند.
5. قطعه‌ها با ترتیب نام معمول در فایل تازه کنارهم قرار می‌گیرند.
6. digest هر دو را می‌خواند؛ باید برابر باشند.

**نتیجه و بررسی:** برابری hash این دو فایل، بازسازی همین داده را تأیید می‌کند. hash دریافتی از منبع ناشناس اعتبار صاحب فایل را ثابت نمی‌کند.

### اشتباه رایج و عیب‌یابی

برای مرتب‌سازی عددی `sort -n` لازم است؛ بدون آن 10 ممکن است قبل از 2 بیاید. `uniq` را روی دادهٔ نامرتب با حذف همهٔ تکرارها اشتباه نگیرید. فایلی بدون newline نهایی ممکن است wc -l کمتر از انتظار بدهد.

### نکته‌های تکمیلی این سرفصل

ابزارهای تکمیلی را با همان ورودی تجربه کنید:

| دستور | شرح اجزا و خروجی |
|---|---|
| `sed 's/ops/infra/g' people.csv` | s جایگزینی؛ ops الگو، infra جایگزین، g همهٔ تطبیق‌های هر خط؛ فایل اصلی دست‌نخورده می‌ماند. |
| `od -An -tx1 -N8 people.csv` | نمایش بایت؛ An بدون offset، tx1 هر بایت hex و N8 فقط هشت بایت اول. |
| `md5sum people.csv` | digest قدیمی MD5؛ برای امنیت برخورد مناسب نیست. |
| `sha512sum people.csv` | digest SHA-512؛ الگوریتم متفاوت، پس با SHA-256 برابر نیست. |
| `gzip -c people.csv > people.gz` | gzip فشرده می‌کند؛ c خروجی روی stdout و > ذخیره در فایل دیگر. |
| `zcat people.gz` | دادهٔ gzip را باز و روی صفحه می‌فرستد؛ فایل فشرده حذف نمی‌شود. |
| `bzip2 -c people.csv > people.bz2` | همان روش با bzip2. |
| `bzcat people.bz2` | خواندن جریان bzip2. |
| `xz -c people.csv > people.xz` | همان روش با xz. |
| `xzcat people.xz` | خواندن جریان xz. |

`tail -f FILE` به خط‌های افزوده‌شده نگاه می‌کند و با Ctrl+C تمام می‌شود. برای فایل log که با rotation جایگزین می‌شود GNU `tail -F` معمولاً مناسب‌تر است. برای join بر مبنای کلید، هر دو فایل باید روی همان کلید مرتب باشند؛ `join -t, a.csv b.csv` ستون اول دو فایل comma-delimited مرتب را وصل می‌کند. هنگام اتمام از پوشه خارج شوید؛ دادهٔ تمرین را برای مرور نگه دارید.

### تمرین مستقل

از people.csv فقط نام‌های یکتا و مرتب را چاپ کنید.

<details>
<summary>پاسخ تشریحی؛ ابتدا خودتان حل کنید</summary>

`cut -d, -f1 people.csv | sort -u`؛ ستون اول نام است و sort -u مرتب‌سازی و حذف تکرار را ترکیب می‌کند. نتیجه ali و sara است.

</details>

## 103.3 — ساخت، کپی، جست‌وجو و آرشیو فایل

### مفهوم و کاربرد

کپی یک فایل مستقل می‌سازد؛ جابه‌جایی نام یا محل را تغییر می‌دهد. `rm` سطل بازیافت عمومی ندارد. wildcard را shell قبل از اجرای دستور باز می‌کند: * صفر یا چند نویسه، ? یک نویسه، [ab] یکی از a/b و [!0-9] یک نویسهٔ غیررقمی.

آرشیو یعنی چند فایل در یک بسته؛ compression یعنی کم‌کردن حجم. tar بدون گزینهٔ فشرده‌سازی الزاماً فشرده نیست.

### مثال 1: چرخهٔ یک فایل

همهٔ تغییرها داخل پوشهٔ موقت خودتان.

```bash
files_lab=$(mktemp -d)
cd "$files_lab"
mkdir -p project/docs backup restore
printf 'Linux
' > project/docs/note.txt
cp -a project/docs backup/
mv project/docs/note.txt project/docs/readme.txt
ls -l project/docs backup/docs
```

**توضیح خط‌به‌خط:**

1. پوشهٔ مستقل ایجاد می‌کند.
2. پوشهٔ کاری را عوض می‌کند.
3. project/docs را همراه والد و دو پوشهٔ دیگر می‌سازد.
4. فایل شش‌بایتی با newline می‌سازد.
5. کپی بازگشتی با حفظ metadata متداول؛ نتیجه backup/docs است.
6. فایل را در همان پوشه تغییر نام می‌دهد.
7. نسخهٔ تغییرنام‌یافته و کپی قدیمی را جدا می‌بینید.

**نتیجه و بررسی:** کپی backup/docs/note.txt مستقل است؛ تغییر readme محتوای کپی را خودکار عوض نمی‌کند.

### مثال 2: جست‌وجوی قابل فهم

بعد از مثال اول.

```bash
touch project/docs/a1.txt project/docs/a2.txt project/docs/.hidden
printf '%s
' project/docs/a?.txt
find project -type f -name '*.txt' -print
find project -type f -mmin -10 -exec ls -lh -- {} +
```

**توضیح خط‌به‌خط:**

1. سه فایل خالی می‌سازد؛ نام آخر مخفی است.
2. shell دو نام a1 و a2 را به‌جای ? پیدا می‌کند؛ printf تنها نشان می‌دهد.
3. از project می‌گردد؛ type f فایل عادی و name الگوی نام است. تکی‌ها جلوی گسترش زودهنگام توسط shell را می‌گیرند.
4. فایل‌های تغییرمحتوا در ده دقیقهٔ اخیر را با ls نشان می‌دهد؛ {} جای مسیرها، + دسته‌بندی و -- پایان گزینه‌های ls است.

**نتیجه و بررسی:** find فایل .hidden را هم می‌بیند ولی آزمون نام *.txt آن را انتخاب نمی‌کند. mtime زمان تغییر محتوا و ctime تغییر metadata/inode است، نه زمان ساخت.

### مثال 3: آرشیو و بازیابی واقعی

بعد از مثال اول؛ restore خالی است.

```bash
tar -czf project.tar.gz project
tar -tzf project.tar.gz
tar -xzf project.tar.gz -C restore
cmp project/docs/readme.txt restore/project/docs/readme.txt
sha256sum project.tar.gz
```

**توضیح خط‌به‌خط:**

1. c ساخت، z gzip، f نام فایل آرشیو؛ project ورودی است.
2. t فهرست محتواست و چیزی استخراج نمی‌کند.
3. x استخراج و C پوشهٔ مقصد است؛ مقصد باید موجود باشد.
4. دو نسخه را بایت‌به‌بایت مقایسه می‌کند؛ سکوت و status صفر یعنی برابر.
5. digest آرشیو را برای تشخیص تغییر آینده می‌سازد.

**نتیجه و بررسی:** وجود فایل tar کافی نیست؛ بازیابی و مقایسه نشان می‌دهد کپی قابل خواندن است. این نسخهٔ روی همان دیسک هنوز backup مستقل نیست.

### مثال 4: کپی بلوکی بدون دیسک واقعی

در همان پوشهٔ تمرین؛ خروجی حتماً فایل عادی جدید است.

```bash
dd if=/dev/zero of=sample.bin bs=1M count=2 status=none
stat -c "%s" sample.bin
file sample.bin
```

**توضیح خط‌به‌خط:**

1. if ورودی صفرساز، of فایل خروجی، bs بلوک 1 MiB و count دو بلوک است؛ status=none آمار را خاموش می‌کند.
2. stat ویژگی فایل، -c قالب، %s اندازهٔ بایت است.
3. نوع داده را تشخیص می‌دهد؛ پسوند الزاماً نوع را تعیین نمی‌کند.

**نتیجه و بررسی:** اندازه 2097152 بایت است. اگر of به دیسک اشاره کند دادهٔ آن را بازنویسی می‌کند؛ در این تمرین هرگز چنین نکنید.

### اشتباه رایج و عیب‌یابی

`cp -r` برای پوشه و `rmdir` فقط پوشهٔ خالی است. برای پاک‌کردن یک فایل آزمایش `rm -i PATH` قبل از حذف می‌پرسد. هرگز برای رفع خطای Permission denied به‌طور خودکار rm را با sudo تکرار نکنید.

### نکته‌های تکمیلی این سرفصل

`ls -a` فایل‌های مخفی، `ls -lh` جزئیات با اندازهٔ خوانا، `ls -R` بازگشتی و `ls -d DIR` خود پوشه را نشان می‌دهد. glob عادی * نام‌های شروع‌شده با نقطه را شامل نمی‌شود. `touch` فایل موجود را خالی نمی‌کند؛ زمان‌ها را تغییر می‌دهد.

برای cpio در همین پوشه: `find project -print0 | cpio --null -ov > project.cpio`؛ find نام‌ها را با NUL جدا می‌کند، --null همان جداکننده را می‌خواند، o ساخت و v نمایش نام است. پوشهٔ خالی cpio-restore را با mkdir بسازید، با cd واردش شوید و `cpio -idmv --no-absolute-filenames < ../project.cpio` بزنید: i استخراج، d ساخت والد، m حفظ زمان، v نمایش نام. به مسیر قبلی با cd .. برگردید. آرشیو خارجی را قبل از استخراج بررسی کنید.

`tar -cjf NAME.tar.bz2 project` از bzip2 و `tar -cJf NAME.tar.xz project` از xz استفاده می‌کند؛ j و J یکسان نیستند. `gzip -k FILE`، `bzip2 -k FILE` و `xz -k FILE` اصل را نگه می‌دارند. `gunzip FILE.gz`، `bunzip2 FILE.bz2` و `unxz FILE.xz` باز می‌کنند و معمولاً فایل فشرده را جایگزین می‌کنند؛ اگر فایل مقصد هست قبل از overwrite تصمیم بگیرید.

### تمرین مستقل

فایل‌های txt بزرگ‌تر از 10 MiB و تغییرکرده در هفت روز اخیر را فقط فهرست کنید.

<details>
<summary>پاسخ تشریحی؛ ابتدا خودتان حل کنید</summary>

`find project -type f -name '*.txt' -size +10M -mtime -7 -print`؛ آزمون‌ها با AND ترکیب می‌شوند. mtime بر پایهٔ دوره‌های ۲۴ساعته است. خالی‌بودن نتیجه با فایل‌های کوچک ما طبیعی است.

</details>

## 103.4 — ورودی، خروجی، خطا و Pipe

### مفهوم و کاربرد

هر پردازه سه مسیر استاندارد دارد: 0 ورودی stdin، 1 خروجی stdout و 2 خطا stderr. `|` خروجی معمولی سمت چپ را ورودی سمت راست می‌کند؛ خطا را خودکار منتقل نمی‌کند. `>` بازنویسی و `>>` افزودن است. redirection را خود shell قبل از اجرای برنامه انجام می‌دهد، پس `cat f > f` فایل را پیش از خواندن خالی می‌کند.

### مثال 1: جداکردن خطا

در پوشهٔ موقت؛ فایل گمشده را عمداً ایجاد نمی‌کنیم.

```bash
io_lab=$(mktemp -d)
cd "$io_lab"
printf 'ok
' > present.txt
ls present.txt missing.txt > output.txt 2> error.txt
cat output.txt
cat error.txt
```

**توضیح خط‌به‌خط:**

1. محیط تمرین را می‌سازد.
2. به آن وارد می‌شود.
3. یک فایل معلوم ایجاد می‌کند.
4. stdout نام موجود به output و stderr مربوط به missing به error می‌رود.
5. باید present.txt را ببینید.
6. باید پیام نبود missing.txt را ببینید؛ متن دقیق به زبان سیستم بستگی دارد.

**نتیجه و بررسی:** این ls به‌خاطر یکی از ورودی‌ها status غیرصفر دارد، حتی با وجود مقداری خروجی موفق.

### مثال 2: ترتیب redirection

در همان پوشه.

```bash
ls present.txt missing.txt > both.txt 2>&1
ls present.txt missing.txt 2>&1 > only-out.txt
cat both.txt
```

**توضیح خط‌به‌خط:**

1. اول stdout فایل می‌شود؛ سپس stderr به مقصد فعلی stdout متصل می‌شود، پس هر دو داخل فایل‌اند.
2. ابتدا stderr به ترمینال فعلی stdout می‌رود؛ سپس فقط stdout فایل می‌شود.
3. نام و پیام خطا را باهم می‌خوانید.

**نتیجه و بررسی:** در خط دوم خطا همچنان روی ترمینال دیده می‌شود. علامت & در 2>&1 به معنی ارجاع descriptor است، نه background.

### مثال 3: tee و تبدیل ورودی به آرگومان

در همان پوشه.

```bash
printf 'red
blue
' | tee colors.txt
printf 'green
' | tee -a colors.txt
touch "two words.txt"
find . -maxdepth 1 -name '*.txt' -type f -print0 | xargs -0 -r sha256sum
```

**توضیح خط‌به‌خط:**

1. printf داده می‌سازد و tee آن را هم نمایش و هم ذخیره می‌کند.
2. گزینهٔ a محتوا را اضافه می‌کند، نه جایگزین.
3. یک نام دارای فاصله را ایجاد می‌کند.
4. find نام‌های فایل را NUL-delimited می‌دهد؛ xargs -0 همان مرزها را می‌خواند و به آرگومان sha256sum تبدیل می‌کند؛ GNU -r در ورودی خالی دستور را اجرا نمی‌کند.

**نتیجه و بررسی:** نام دارای فاصله یک فایل می‌ماند؛ xargs عادی آن را می‌شکست. hashها دادهٔ سیستم نیستند و در پوشهٔ تمرین محاسبه می‌شوند.

### اشتباه رایج و عیب‌یابی

`sudo echo text > /etc/file` مجوز نوشتن shell را بالا نمی‌برد؛ برای نوشتن مدیریتی کنترل‌شده از sudoedit یا tee با sudo استفاده می‌شود. اینجا نیازی به نوشتن /etc نداریم.

### نکته‌های تکمیلی این سرفصل

`kernel=$(uname -r)` خروجی دستور را در متغیر می‌گیرد؛ `printf "%s\n" "$kernel"` آن را چاپ می‌کند. جایگزینی فرمان trailing newlineها را حذف می‌کند. `/dev/null` خروجی نوشته‌شده را دور می‌ریزد؛ برای یادگیری خطاها را بی‌دلیل به آن نفرستید.

### تمرین مستقل

چگونه تعداد سطرهای colors.txt را بدون نمایش نام فایل چاپ می‌کنید؟

<details>
<summary>پاسخ تشریحی؛ ابتدا خودتان حل کنید</summary>

`wc -l < colors.txt`؛ فایل روی stdin است و wc نام آرگومان فایلی ندارد. عدد 3 را انتظار داریم.

</details>

## 103.5 — برنامهٔ در حال اجرا و مدیریت پردازه

### مفهوم و کاربرد

فایل برنامه با پردازه فرق دارد؛ هر اجرای برنامه یک PID دارد. PPID شناسهٔ والد است. Job نگاه shell به کار شروع‌شده از همان shell است و شمارهٔ %1 با PID یکی نیست. SIGTERM درخواست پایان با فرصت پاک‌سازی و SIGKILL پایان غیرقابل‌مدیریت است. اول باید مطمئن شوید کدام PID را هدف گرفته‌اید.

### مثال 1: ساخت پردازهٔ خودمان

در shell تعاملی؛ فقط پردازهٔ تمرین را متوقف می‌کنیم.

```bash
sleep 300 &
lab_pid=$!
jobs -l
ps -p "$lab_pid" -o pid,ppid,stat,cmd
kill -TERM "$lab_pid"
wait "$lab_pid"
```

**توضیح خط‌به‌خط:**

1. sleep سیصد ثانیه منتظر می‌ماند؛ & آن را پس‌زمینه می‌کند.
2. شناسهٔ آخرین کار پس‌زمینه در متغیر نگه داشته می‌شود.
3. جدول jobهای همین shell همراه PID را می‌بینید.
4. همان PID و والد، وضعیت و دستورش را انتخاب می‌کند.
5. فقط به sleep خودمان درخواست پایان می‌فرستد.
6. shell منتظر پایان همان فرزند می‌شود؛ status غیرصفر برای خاتمه با سیگنال طبیعی است.

**نتیجه و بررسی:** وضعیت sleep اغلب S است. بعد از پایان، ps دیگر آن PID را نشان نمی‌دهد. PID قدیمی را در جلسهٔ دیگری دوباره استفاده نکنید.

### مثال 2: توقف و ادامهٔ تعاملی

کلیدهای جدول را در shell بزنید؛ این بلوک دستور قابل paste نیست.

```text
sleep 300
Ctrl+Z
jobs -l
bg %1
fg %1
Ctrl+C
```

**توضیح خط‌به‌خط:**

1. دستور را بدون & اجرا کنید؛ ترمینال تا پایان منتظر است.
2. پردازه را موقتاً متوقف می‌کند، پایان نمی‌دهد.
3. شمارهٔ job متوقف‌شده را بخوانید؛ در shell تازه معمولاً 1 است.
4. اگر شماره 1 بود آن را در پس‌زمینه ادامه می‌دهد؛ شمارهٔ واقعی را استفاده کنید.
5. همان job را پیش‌زمینه می‌آورد.
6. به کار پیش‌زمینه SIGINT می‌دهد و sleep خاتمه می‌یابد.

**نتیجه و بررسی:** تفاوت Stopped و Done را می‌بینید. bg برنامه‌ای را که از stdin می‌خواند ممکن است دوباره متوقف کند.

### مثال 3: پایش و خروج از ابزار

بدون تغییر پردازه‌های سیستم.

```bash
ps -eo pid,user,stat,%cpu,%mem,cmd --sort=-%cpu
pgrep -a -x sleep
uptime
free -h
top
```

**توضیح خط‌به‌خط:**

1. e همهٔ پردازه‌ها، o ستون‌ها و sort مرتب‌سازی نزولی CPU است.
2. پردازه‌های نام دقیق sleep را با خط اجرا می‌بیند؛ a جزئیات و x تطبیق کامل نام است.
3. مدت روشن‌بودن، کاربران و load average را می‌خواند.
4. حافظه و swap را با واحد خوانا می‌بیند.
5. نمای به‌روز پردازه‌ها را باز می‌کند؛ با q خارج شوید.

**نتیجه و بررسی:** R آماده/درحال اجرا، S انتظار قابل وقفه، D انتظار غیرقابل وقفه، T متوقف و Z پایان‌یافتهٔ تحویل‌گزارش‌نشده به والد است. load درصد CPU نیست.

### اشتباه رایج و عیب‌یابی

`pkill` و `killall` می‌توانند چند پردازه را بزنند. با `pgrep -a -x NAME` دامنه را اول ببینید. پردازهٔ D ممکن است حتی با SIGKILL تا بازگشت I/O ناپدید نشود؛ تکرار kill علت ذخیره‌سازی را رفع نمی‌کند.

### نکته‌های تکمیلی این سرفصل

برای اجرای جدا از قطع ترمینال در پوشهٔ تمرین: `nohup sleep 60 > nohup.log 2>&1 &`؛ nohup بی‌اعتنایی به SIGHUP، > فایل خروجی، 2>&1 همراه‌کردن خطا و & پس‌زمینه است. PID را با `$!` نگه دارید و در صورت نیاز با TERM خاتمه دهید. nohup تضمین زنده‌ماندن پس از reboot یا سیاست پایان‌دادن نشست نیست.

`tmux new -s lpic` نشست می‌سازد؛ Ctrl+B سپس D جدا می‌شود؛ `tmux attach -t lpic` برمی‌گردد و `exit` داخل shell آن را تمام می‌کند. در screen، `screen -S lpic` ساخت، Ctrl+A سپس D جداسازی و `screen -r lpic` بازگشت است. ابزار باید نصب باشد. `watch -n 2 uptime` هر دو ثانیه uptime را تکرار می‌کند؛ Ctrl+C خروج. `ps aux` سبک BSD و `ps -ef` سبک گزینه‌های Unix است؛ a/u/x و e/f را بی‌هدف مخلوط نکنید.

### تمرین مستقل

آیا Ctrl+Z همان kill است؟ چرا فایل باز ممکن است باقی بماند؟

<details>
<summary>پاسخ تشریحی؛ ابتدا خودتان حل کنید</summary>

خیر، فقط توقف است. پردازه و منابعش هنوز وجود دارند. برای پایان مرتب، آن را ادامه دهید و SIGTERM یا روش خروج خود برنامه را به‌کار ببرید.

</details>

## 103.6 — اولویت پردازه‌ها

### مفهوم و کاربرد

nice سهم نسبی CPU هنگام رقابت را تحت تأثیر می‌گذارد، نه درصد ثابت CPU یا RAM. عدد کوچک‌تر معمولاً اولویت بیشتر دارد؛ بازهٔ رایج -20 تا 19 است. مقدار اولیه معمولاً صفر است اما از والد ارث می‌رسد. کاربر عادی معمولاً می‌تواند پردازهٔ خودش را کم‌اولویت‌تر کند؛ افزایش اولویت به مجوز/limit مناسب نیاز دارد.

### مثال 1: دیدن مقدار ارثی

بدون تغییر.

```bash
ps -p $$ -o pid,ni,comm
nice
```

**توضیح خط‌به‌خط:**

1. $$ شناسهٔ shell؛ ni مقدار nice و comm نام است.
2. بدون دستور، مقدار nice فعلی را گزارش می‌کند.

**نتیجه و بررسی:** در shell معمولی صفر است؛ اگر میزبان سیاست دیگری دارد عدد فرق می‌کند.

### مثال 2: شروع با اولویت کمتر

یک sleep آموزشی ایجاد می‌شود.

```bash
nice -n 10 sleep 300 &
priority_pid=$!
ps -p "$priority_pid" -o pid,ni,comm
```

**توضیح خط‌به‌خط:**

1. nice مقدار 10 را به مقدار ارثی اضافه و sleep را پس‌زمینه می‌کند؛ در مبنای صفر نتیجه 10 است.
2. PID برای کار بعدی ذخیره می‌شود.
3. عدد واقعی را بررسی می‌کند؛ به فرض صفر بسنده نکنید.

**نتیجه و بررسی:** در مبنای معمول NI=10؛ sleep کار CPUمحور نیست، پس این مثال مقدار را آموزش می‌دهد نه benchmark کارایی.

### مثال 3: تغییر و جمع‌کردن تمرین

بلافاصله بعد از مثال دوم در همان shell.

```bash
renice --priority 19 --pid "$priority_pid"
ps -p "$priority_pid" -o pid,ni,pri,comm
kill -TERM "$priority_pid"
wait "$priority_pid"
```

**توضیح خط‌به‌خط:**

1. با گزینه‌های بلند util-linux، مقدار مطلق nice پردازهٔ مشخص به 19 می‌رود.
2. NI جدید و ستون priority زمان‌بند را می‌خواند؛ PRI با NI یک ستون یکسان نیست.
3. sleep آموزشی را خاتمه می‌دهد.
4. پایان فرزند را جمع می‌کند؛ status سیگنال طبیعی است.

**نتیجه و بررسی:** NI باید 19 باشد. `renice -n 15 -p PID` شکل رایج آزمونی است؛ معنای نسبی/مطلق -n در بعضی پیاده‌سازی‌ها یا POSIXLY_CORRECT تفاوت دارد، لذا manual محلی را بخوانید.

### اشتباه رایج و عیب‌یابی

بالابردن nice از 10 به 19 مجاز بودنِ پایین‌آوردن دوباره از 19 به 10 را تضمین نمی‌کند. Permission denied را با تغییر تصادفی مالک پردازه حل نکنید.

### تمرین مستقل

بین nice برابر 5 و 15، کدام در شرایط معمول سهم بهتری دارد؟ آیا 5 یعنی پنج درصد؟

<details>
<summary>پاسخ تشریحی؛ ابتدا خودتان حل کنید</summary>

عدد 5 اولویت بهتری دارد. درصد ثابت نیست؛ رقابت، scheduler و cgroup هم اثر دارند.

</details>

## 103.7 — الگوهای متن و عبارت منظم

### مفهوم و کاربرد

Regex زبان توصیف الگوی متن است؛ glob زبان انتخاب نام فایل توسط shell. در regex، `a*` صفر یا چند a است؛ در glob یعنی نامی که با a شروع شود. `^` ابتدای خط، `$` انتها، `.` یک نویسه، `[0-9]` رقم و `[^0-9]` غیررقم است.

grep عادی BRE، grep -E عبارت گستردهٔ ERE و grep -F متن ثابت می‌خواهد. در ERE، + حداقل یکی، ? صفر/یک، {m,n} شمار تکرار، پرانتز گروه و | یا است. شکل‌های egrep/fgrep تاریخی‌اند.

### مثال 1: داده و انتخاب کامل خط

محیط مستقل از مثال‌های قبل.

```bash
regex_lab=$(mktemp -d)
cd "$regex_lab"
printf 'yes
no
yesterday
error: disk
warning: ram
literal.*
' > lines.txt
grep -E '^(yes|no)$' lines.txt
grep -F 'literal.*' lines.txt
```

**توضیح خط‌به‌خط:**

1. پوشهٔ تمرین ایجاد می‌شود.
2. به آن وارد می‌شویم.
3. شش خط با تفاوت‌های عمدی می‌سازیم.
4. E زبان گسترده، ^ و $ الزام کل خط و گروه yes|no انتخاب یکی از دو کلمه است.
5. F نقطه و ستاره را عیناً می‌خواهد، نه معنای regex.

**نتیجه و بررسی:** اول yes و no، سپس literal.* دیده می‌شود؛ yesterday به‌علت $ در انتخاب اول نیست.

### مثال 2: انتخاب، شمارش و وارونه‌کردن

در همان پوشه.

```bash
grep -nE '^(error|warning):' lines.txt
grep -c '^y' lines.txt
grep -v '^y' lines.txt
```

**توضیح خط‌به‌خط:**

1. n شمارهٔ خط و E الگوی OR را فعال می‌کند؛ دونقطه باید بعد از کلمه باشد.
2. c تعداد خط‌های شروع‌شده با y را می‌دهد؛ تعداد تطبیق‌های درون هر خط نیست.
3. v انتخاب را وارونه می‌کند؛ خط‌هایی که با y شروع نمی‌شوند چاپ می‌شوند.

**نتیجه و بررسی:** شماره‌های 4 و 5 برای پیام‌ها و عدد 2 برای خط‌های شروع‌شده با y دیده می‌شود.

### مثال 3: جایگزینی و حذف در خروجی

فایل اصلی تغییر نمی‌کند.

```bash
sed 's/error/problem/g' lines.txt
sed '/^warning:/d' lines.txt
grep '^warning:' lines.txt
```

**توضیح خط‌به‌خط:**

1. s جایگزینی؛ g همهٔ تطبیق‌های هر سطر. فقط خط error تغییر می‌کند.
2. بین /ها نشانی الگوست؛ d خط منطبق را از خروجی حذف می‌کند.
3. هنوز همان خط در فایل اصلی موجود است و این را اثبات می‌کند.

**نتیجه و بررسی:** پیام warning در نتیجهٔ sed دوم نیست ولی grep آخر آن را می‌بیند.

### اشتباه رایج و عیب‌یابی

`[yes|no]` به‌معنی واژهٔ yes یا no نیست؛ یک نویسه از مجموعه است. IP شبیه به عدد با regex ساده الزاماً آدرس معتبر نیست. sed -i تغییر واقعی است؛ اول خروجی را ببینید.

### نکته‌های تکمیلی این سرفصل

در GNU BRE می‌توان `\(yes\|no\)` را نوشت؛ | در BRE پایهٔ POSIX یک عملگر استاندارد نیست و این شکل GNU extension است. برای خوانایی و portability مناسبِ ERE از grep -E استفاده کنید. `[[:space:]]` کلاس فاصله و tab است؛ `grep -v '^[[:space:]]*#' FILE` commentها را حذف می‌کند اما خط خالی را نه. grep برای match کد صفر، نبود match کد 1 و خطای اجرا معمولاً 2 برمی‌گرداند.

### تمرین مستقل

خطی را انتخاب کنید که فقط دو تا چهار رقم دارد؛ چرا ^ و $ مهم‌اند؟

<details>
<summary>پاسخ تشریحی؛ ابتدا خودتان حل کنید</summary>

`grep -E '^[0-9]{2,4}$' FILE`؛ بدون anchor متن اضافی در ابتدا یا انتها هم ممکن است پذیرفته شود. FILE باید دادهٔ تمرین شما باشد.

</details>

## 103.8 — ویرایش با vi از اولین ورود

### مفهوم و کاربرد

vi حالت دارد: در Normal کلیدها فرمان‌اند؛ در Insert متن نوشته می‌شود؛ با : فرمان ذخیره و خروج می‌دهیم. Esc راه برگشت مطمئن به Normal است. vim نسخهٔ توسعه‌یافتهٔ vi است؛ بعضی میان‌برها مثل gg در همهٔ viهای قدیمی نیستند. برای رفتن به خط اول از 1G هم می‌توان استفاده کرد.

در این درس «کلید» را با «دستور Bash» مخلوط نکنید. Enter را فقط جایی که گفته شده بزنید.

### مثال 1: ساخت و ذخیره

ابتدا در پوشهٔ تمرین با `vi first.txt` فایل تازه را باز کنید؛ سپس کلیدهای زیر داخل ویرایشگر هستند.

```text
i
Linux is useful.
Practice every day.
Esc
:wq
```

**توضیح خط‌به‌خط:**

1. از Normal به Insert می‌رود تا بتوانید بنویسید.
2. این متن را تایپ و یک Enter بزنید.
3. خط دوم را بنویسید.
4. به Normal برمی‌گردد.
5. دونقطه، wq و Enter؛ فایل را می‌نویسد و خارج می‌شود.

**نتیجه و بررسی:** در shell با `cat first.txt` دو خط را ببینید. اگر readonly است مسیر و مجوز را بررسی کنید؛ :w! مجوز سیستم‌عامل را دور نمی‌زند.

### مثال 2: حرکت، کپی و undo

دوباره vi first.txt را باز کنید؛ از Normal آغاز کنید.

```text
1G
yy
p
dd
u
:q!
```

**توضیح خط‌به‌خط:**

1. به خط اول می‌رود.
2. کل خط فعلی را در register کپی می‌کند.
3. بعد از خط فعلی می‌چسباند؛ سه خط می‌شود.
4. خط فعلی را حذف/برش می‌دهد.
5. آخرین تغییر را برمی‌گرداند.
6. با Enter همهٔ تغییرهای ذخیره‌نشده را کنار می‌گذارد و خارج می‌شود.

**نتیجه و بررسی:** فایل روی دیسک همچنان همان دو خط اولیه است؛ undo با خروج بدون ذخیره فرق دارد.

### مثال 3: جست‌وجو و اصلاح

دوباره فایل را باز کنید.

```text
/Practice
cw
Study
Esc
:w
ZZ
```

**توضیح خط‌به‌خط:**

1. جست‌وجوی رو به جلو؛ پس از عبارت Enter بزنید.
2. از ابتدای واژهٔ Practice آن را برای تغییر حذف و وارد Insert می‌شود.
3. جایگزین را بنویسید.
4. به Normal برگردید.
5. ذخیره با Enter، بدون خروج.
6. دو Z بزرگ؛ ذخیره در صورت نیاز و خروج.

**نتیجه و بررسی:** خط دوم اکنون Study every day. است. در فایل فقط یک Practice داشتیم؛ با متن دیگر نتیجه را خودتان بررسی کنید.

### اشتباه رایج و عیب‌یابی

وقتی با زدن j حرف j نوشته می‌شود در Insert هستید؛ Esc بزنید. گیرکردن در ویرایشگر را با بستن ترمینال حل نکنید؛ :q! یا :wq را آگاهانه انتخاب کنید.

### نکته‌های تکمیلی این سرفصل

| کلید در Normal | کاربرد |
|---|---|
| h، j، k، l | چپ، پایین، بالا، راست |
| w، b | آغاز واژهٔ بعد/قبل |
| 0، $ | ابتدای خط/پایان خط |
| G، 1G | آخرین/اولین خط |
| x، dw، dd | حذف نویسه، تا واژهٔ بعد، کل خط |
| y، d | عملگر کپی/حذف؛ با حرکت ترکیب می‌شود، مانند yw یا d$ |
| /text، ?text | جست‌وجوی جلو/عقب؛ Enter اجرا می‌کند |
| n، N | تکرار در جهت جست‌وجو/جهت مخالف |
| :w، :q، :q!، :w! | ذخیره، خروج مشروط، خروج اجباری بدون ذخیره، تلاش ذخیرهٔ اجباری |

در shell، `export EDITOR=vi` و `export VISUAL=vi` انتخاب ویرایشگر را برای ابزارهای پشتیبان تنظیم می‌کنند؛ الزام نمی‌کند همهٔ برنامه‌ها از vi استفاده کنند. Nano معمولاً ساده‌تر و Emacs محیط ویرایش قابل توسعه است، اما تمرین vi برای این سرفصل لازم است.

### تمرین مستقل

فرق i، a و o چیست؟ چطور بدون ذخیره خارج می‌شوید؟

<summary>پاسخ تشریحی؛ ابتدا خودتان حل کنید</summary>

i قبل مکان‌نما وارد درج، a بعد آن و o خط جدید زیر خط فعلی باز می‌کند. Esc سپس :q! و Enter خروج بدون ذخیره است.

</details>
