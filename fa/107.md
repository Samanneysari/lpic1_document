# 107 — کاربران، زمان‌بندی، زبان و منطقهٔ زمانی

[فهرست دوره](README.md)

**پیش‌نیاز:** فصل‌های 103 تا 105؛ تغییر حساب فقط در VM مصرفی

مثال‌ها را به ترتیب هر درس در همان ترمینال اجرا کنید. «خروجی نمونه» عین خروجی همهٔ دستگاه‌ها نیست؛ نام‌ها، شماره‌ها و نسخه‌ها ممکن است فرق کنند. بلوک `text` داده یا پاسخ تعاملی است و نباید به‌عنوان دستور Bash اجرا شود.

## 107.1 — مدیریت حساب و گروه

### مفهوم و کاربرد

کاربر با نام دیده می‌شود ولی هسته بیشتر با UID کار می‌کند. گروه اصلی با GID و گروه‌های تکمیلی برای دسترسی مشترک‌اند. `/etc/passwd` هفت فیلد نام، placeholder رمز، UID، GID، توضیح، home و shell دارد. hash رمز و عمر آن در `/etc/shadow` محافظت می‌شود. `/etc/group` گروه و اعضای تکمیلی و `/etc/gshadow` دادهٔ محافظت‌شدهٔ گروه را نگه می‌دارد.

`getent` مطابق NSS کار می‌کند؛ بنابراین حساب LDAP و منبع‌های دیگر را هم می‌تواند ببیند. خواندن مستقیم passwd فقط حساب محلی را نشان می‌دهد.

### مثال 1: خواندن هویت

بدون تغییر.

```bash
whoami
id
getent passwd "$USER"
getent group "$(id -gn)"
```

**توضیح خط‌به‌خط:**

1. نام کاربر مؤثر فعلی را می‌گوید.
2. UID، گروه اصلی و گروه‌های تکمیلی کاربر فعلی را نشان می‌دهد.
3. رکورد حساب از مسیر NSS را می‌خواند؛ `$USER` نام محیط فعلی است.
4. `id -gn` نام گروه اصلی را می‌سازد و getent رکورد آن را می‌خواند.

**نتیجه و بررسی:** در passwd فیلد دوم معمولاً x است؛ hash را چاپ نکنید. shell مثل /usr/sbin/nologin می‌تواند ورود تعاملی را منع کند.

### مثال 2: ساخت و بررسی حساب آزمایش

فقط VM دارای console؛ نام lpicstudent باید آزاد باشد.

```bash
getent passwd lpicstudent
sudo groupadd lpiclab
sudo useradd -m -s /bin/bash -c "LPIC Student" -G lpiclab lpicstudent
sudo passwd lpicstudent
id lpicstudent
```

**توضیح خط‌به‌خط:**

1. پیش از ساخت، نبود نام را بررسی می‌کند؛ خروجی خالی و status 2 معمولاً یعنی نیست.
2. گروه تازه می‌سازد و GID آزاد تخصیص می‌دهد.
3. m ساخت home، s shell، c توضیح و G گروه تکمیلی است.
4. رمز را تعاملی می‌گیرد؛ رمز در history قرار نمی‌گیرد.
5. هویت و عضویت را تأیید می‌کند.

**نتیجه و بررسی:** home باید وجود داشته و lpiclab در groups دیده شود. رفتار پیش‌فرض useradd بین توزیع‌ها فرق دارد؛ گزینه‌ها را صریح دادیم.

### مثال 3: تغییر، قفل و پاک‌سازی

پس از مثال قبل؛ پیش از حذف مطمئن شوید دادهٔ لازم ندارد.

```bash
sudo usermod -aG adm lpicstudent
sudo chage -M 90 -W 14 lpicstudent
sudo passwd -l lpicstudent
sudo chage -l lpicstudent
sudo userdel -r lpicstudent
sudo groupdel lpiclab
```

**توضیح خط‌به‌خط:**

1. a همراه G عضویت adm را اضافه می‌کند و گروه‌های قبلی را نگه می‌دارد؛ اگر adm نیست گروه آزمایش دوم بسازید.
2. حداکثر عمر رمز 90 و هشدار 14 روزه است.
3. ورود مبتنی بر password را قفل می‌کند؛ کلید SSH الزاماً بسته نمی‌شود.
4. سیاست عمر را خوانا نمایش می‌دهد.
5. حساب و home مدیریت‌شده را حذف می‌کند؛ فایل‌های جای دیگر خودکار تضمین نمی‌شوند.
6. گروه آزمایش را پس از نبود استفاده حذف می‌کند.

**نتیجه و بررسی:** پیش از userdel با `sudo find / -xdev -uid UID -print` فایل‌های همان UID را پیدا کنید؛ UID عدد واقعی را از id یادداشت کنید. در سیستم ارزشمند حذف را بدون تصمیم مالک داده انجام ندهید.

### اشتباه رایج و عیب‌یابی

`usermod -G` بدون `-a` فهرست گروه‌های تکمیلی را جایگزین می‌کند. `usermod -u` کوچک UID را عوض می‌کند ولی `-U` بزرگ unlock است. قفل رمز، نشست‌های فعال را نمی‌بندد.

### نکته‌های تکمیلی این سرفصل

`groupmod -n NEW OLD` نام گروه، `groupdel NAME` حذف گروه، `passwd -u USER` بازکردن password و `chage -E 0 USER` منقضی‌کردن حساب است. انقضای حساب با انقضای رمز فرق دارد. `/etc/skel` هنگام ساخت home الگو می‌دهد؛ تغییر آن حساب‌های قبلی را عوض نمی‌کند. بعد از افزودن گروه، پردازهٔ فعلی لیست قدیمی را دارد؛ ورود تازه لازم است. حذف حساب پیش از انتقال مالکیت فایل‌ها می‌تواند داده را با UID عددی بدون نام باقی بگذارد.

### تمرین مستقل

برای service account بدون login چه تنظیمی می‌دهید؟

## 107.2 — اجرای کار در آینده: cron، at و timer

### مفهوم و کاربرد

cron برای برنامهٔ تکراری، at برای یک بار و systemd timer برای زمان‌بندی مرتبط با unit است. crontab کاربر پنج فیلد دقیقه، ساعت، روز ماه، ماه، روز هفته و سپس فرمان دارد. `/etc/crontab` یک فیلد user اضافه دارد. وقتی هم روز ماه و هم روز هفته محدود باشند، رفتار OR در cronهای رایج مهم است؛ manual محلی را بخوانید.

محیط cron کوچک است؛ مسیر کامل، مجوز فایل، working directory و خروجی را صریح کنید. `%` در command بعضی cronها معنی ویژه دارد.

### مثال 1: خواندن و ساخت job امن

در crontab کاربر عادی؛ ابتدا `crontab -l` را ذخیره/ببینید.

```bash
mkdir -p "$HOME/lpic-cron"
crontab -e
* * * * * /usr/bin/date --iso-8601=seconds >> "$HOME/lpic-cron/run.log" 2>&1
crontab -l
```

**توضیح خط‌به‌خط:**

1. پوشهٔ خروجی شخصی می‌سازد.
2. ویرایشگر crontab همین کاربر را باز می‌کند.
3. هر دقیقه date با مسیر کامل اجرا و خروجی/خطا افزوده می‌شود؛ این سطر را در ویرایشگر وارد کنید.
4. پس از ذخیره، entry نصب‌شده را می‌خواند.

**نتیجه و بررسی:** پس از دو دقیقه باید حداقل یک سطر در run.log باشد. سپس دوباره `crontab -e` و فقط همان سطر lab را حذف کنید؛ `crontab -r` همهٔ کارهای کاربر را حذف می‌کند و برای cleanup اینجا مناسب نیست.

### مثال 2: یک کار at

سرویس atd و فرمان at باید نصب و فعال باشند.

```bash
printf "/usr/bin/date --iso-8601=seconds > %s/lpic-at.txt
" "$HOME" | at now + 2 minutes
atq
at -c JOB_ID
atrm JOB_ID
```

**توضیح خط‌به‌خط:**

1. printf فرمان کامل را می‌سازد و pipe به at می‌دهد؛ اجرای یک‌باره دو دقیقه بعد.
2. شماره و زمان کارهای صف را می‌بیند.
3. با شمارهٔ واقعی متن wrapper و فرمان صف را می‌خواند.
4. فقط اگر می‌خواهید پیش از اجرا لغو کنید؛ شمارهٔ واقعی را جایگزین کنید.

**نتیجه و بررسی:** اگر اجازه رد شد فایل‌های allow/deny و سرویس atd را بررسی کنید. مسیر HOME هنگام تولید در فرمان نهایی قرار گرفته است.

### مثال 3: timer کاربر بدون root

دو فایل زیر را در ~/.config/systemd/user بسازید.

```ini
[Service]
Type=oneshot
ExecStart=/usr/bin/date --iso-8601=seconds
[Timer]
OnActiveSec=2m
Unit=lpic-report.service
[Install]
WantedBy=timers.target
systemctl --user daemon-reload
systemctl --user enable --now lpic-report.timer
systemctl --user list-timers --all
journalctl --user -u lpic-report.service --no-pager
```

**توضیح خط‌به‌خط:**

1. محتوای `lpic-report.service`: کار یک‌باره و فرمان با مسیر کامل.
2. محتوای `lpic-report.timer`: دو دقیقه پس از فعال‌شدن، سرویس را صدا می‌زند و قابل enable است.
3. فایل‌های unit کاربر را بازخوانی می‌کند.
4. برای نشست‌های مربوط enable و همین حالا start می‌کند.
5. موعد بعد و قبلی را می‌خواند.
6. نتیجهٔ اجرا را در journal کاربر می‌خواند.

**نتیجه و بررسی:** برای cleanup: disable --now همان timer، سپس حذف فقط دو فایل lab و daemon-reload. timer کاربر پس از logout فقط با linger/session مناسب ادامه دارد.

### اشتباه رایج و عیب‌یابی

فرمان طولانی و وابسته به shell را مستقیم در cron نریزید؛ script تست‌شده بسازید. jobی که دستی کار می‌کند ممکن است در cron به‌خاطر PATH یا مجوز شکست بخورد.

### نکته‌های تکمیلی این سرفصل

`/etc/cron.allow` و deny و همتای at دسترسی را کنترل می‌کنند؛ تقدم و نبود فایل‌ها پیاده‌سازی‌محور است. spool زیر `/var/spool/cron` یا crontabs را مستقیم ویرایش نکنید. Timer تقویمی از `OnCalendar=*-*-* 02:15:00` استفاده می‌کند؛ `Persistent=true` اجرای تقویمی ازدست‌رفته در خاموشی را ممکن است پس از بالا آمدن جبران کند. `RandomizedDelaySec=5m` بار همزمان را پخش می‌کند. `systemd-run --user --on-active=5m /usr/bin/printf "done\n"` timer گذرای کاربر می‌سازد.

### تمرین مستقل

سطر `15 2 * * 1-5 /usr/local/bin/report` چه زمانی است؟

## 107.3 — زبان، encoding و ساعت محلی

### مفهوم و کاربرد

Unicode مجموعهٔ نویسه‌ها و UTF-8 یکی از روش‌های کدکردن آن‌هاست. ASCII زیرمجموعهٔ کوچک و ISO-8859 خانوادهٔ encoding تک‌بایتی قدیمی است. Locale بر زبان پیام، مرتب‌سازی، قالب عدد/تاریخ و کلاس نویسه اثر دارد. `LANG` پیش‌فرض، `LC_*` override همان دسته و `LC_ALL` override همه است.

Timezone فقط نمایش یک لحظه را عوض می‌کند؛ ساعت واقعی جهانی را جابه‌جا نمی‌کند. `/usr/share/zoneinfo` دادهٔ منطقه و `/etc/localtime` انتخاب فعال است.

### مثال 1: اثر locale روی یک فرمان

بدون تغییر سراسری.

```bash
locale
locale -a
printf 'z
ä
a
' > names.txt
LC_ALL=C sort names.txt
printf "%s
" "$LANG" "$LC_ALL"
```

**توضیح خط‌به‌خط:**

1. مقادیر فعال را نشان می‌دهد.
2. localeهای نصب‌شده را فهرست می‌کند.
3. سه خط UTF-8 می‌سازد.
4. فقط برای همین فرمان ترتیب بایتی C را اعمال می‌کند.
5. مقدار محیط shell را می‌خواند؛ LC_ALL ممکن است خالی باشد.

**نتیجه و بررسی:** ترتیب locale زبانی ممکن است متفاوت باشد؛ در script parsing، C خروجی قابل پیش‌بینی‌تری می‌دهد. این فرمان تنظیم جهانی را عوض نمی‌کند.

### مثال 2: تبدیل encoding

ورودی معلوم را خودمان از UTF-8 به Latin-1 و برمی‌گردانیم.

```bash
printf 'café
' > utf8.txt
iconv -f UTF-8 -t ISO-8859-1 utf8.txt > latin1.txt
iconv -f ISO-8859-1 -t UTF-8 latin1.txt > restored.txt
cmp utf8.txt restored.txt
```

**توضیح خط‌به‌خط:**

1. متن UTF-8 می‌سازد.
2. f encoding ورودی و t خروجی است.
3. مسیر معکوس را انجام می‌دهد.
4. سکوت و status صفر برابری بایت‌های اول و آخر را ثابت می‌کند.

**نتیجه و بررسی:** اگر encoding مبدأ را اشتباه حدس بزنید ممکن است خطا یا متن خراب شود. file فقط حدس می‌زند و همیشه encoding را قطعی نمی‌داند.

### مثال 3: Timezone بدون تغییر سیستم

فقط محیط همان فرمان.

```bash
TZ=UTC date --iso-8601=seconds
TZ=Asia/Tehran date --iso-8601=seconds
timedatectl status
readlink -f /etc/localtime
```

**توضیح خط‌به‌خط:**

1. لحظه را به UTC نمایش می‌دهد.
2. همان لحظه با offset منطقهٔ تهران نمایش داده می‌شود.
3. زمان محلی، جهانی، RTC و وضعیت sync را می‌خواند.
4. فایل zone فعال را، اگر symlink باشد، دنبال می‌کند.

**نتیجه و بررسی:** ثانیه‌ها نزدیک‌اند ولی ساعت/offset فرق دارد. نام zone باید در `timedatectl list-timezones` وجود داشته باشد.

### اشتباه رایج و عیب‌یابی

LC_ALL را سراسری و بدون دلیل در profile نگذارید؛ override تنظیم زبانی کاربر را بی‌اثر می‌کند. `tzselect` معمولاً پیشنهاد TZ می‌دهد و خود سیستم را حتماً تغییر نمی‌دهد.

### نکته‌های تکمیلی این سرفصل

در VM آزمایش می‌توان با `sudo timedatectl set-timezone Europe/Berlin` zone را persistent تغییر داد؛ پیش از آن مقدار قبلی را از timedatectl یادداشت و در پایان بازگردانید. `/etc/timezone` روی بعضی توزیع‌ها نام را نگه می‌دارد. `date` نمایش/تنظیم زمان، TZ متغیر process و timedatectl ابزار systemd است. تغییر دستی ساعت می‌تواند log، TLS و پایگاه داده را خراب کند؛ همگام‌سازی فصل 108 را ترجیح دهید.

### تمرین مستقل

برای پردازش قابل پیش‌بینی خروجی ابزار در script چه می‌نویسید؟

<summary>پاسخ تشریحی؛ ابتدا خودتان حل کنید</summary>

</details>
